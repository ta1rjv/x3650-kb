Troubleshooting Guide

How to diagnose an x3650 M3 - where errors are reported, light path LEDs, POST codes, IMM event ids, the SEL, sensors, DSA Preboot, and a symptom-to-source table.

The x3650 M3 reports problems through several channels that complement each other. This guide shows which channel to read first and how to decode what it shows. The complete catalogues (655 IMM event ids, 45 POST codes, 63 DSA messages, symptom tables) are in the Error codes volume; everything there is DOCUMENTED from the Problem Determination and Service Guide (S-004, 16th edition) and cross-checked against the archived infocenter. Actions marked "trained service technician only" in S-004 are kept that way.

Where errors appear #

Channel What it holds How to read it
Light path diagnostics panel LEDs per subsystem; stay lit only while AC is connected Slide the blue release latch on the operator information panel left and pull the panel out
System-board and riser LEDs Error LEDs next to DIMMs, CPUs, fans, PCI slots; 12 V power-channel LEDs A-E and AUX; IMM heartbeat Cover removed, AC connected
Checkpoint display Two-digit code of the last boot step reached; not an error code Light path panel
POST event log The three most recent POST error codes F1 Setup -> System Event Logs -> POST Event Viewer
System event log (SEL) All BMC, POST and SMI events; fixed size; when full, new entries are NOT written F1 Setup -> System Event Log; ipmitool sel elist; DSA ("IPMI event log")
IMM event log Filtered text messages with event ids, plus IMM events (logins, network changes) IMM web Event Log; CLI readlog; DSA ("ASM event log")
DSA log Merge of SEL, IMM log and OS logs plus test results DSA Preboot (F2 at POST) or DSA Portable
Beep codes None: "This server does not use beep codes for server status" -

Source: S-004 pp.28-31, 274, 360; S-020 pp.97-98 (Error codes 2, 8).

Severities: Information (no action), Warning (possible problem) and Error (may need action); the IMM web log marks Warning "W" and Error "E" (S-004 p.31, S-020 p.99).

Step 1: the light path panel #

The panel (S-004 Fig 4) has three rows of LEDs, a Remind button, a recessed NMI button, the checkpoint display and a recessed Reset button (Hardware 6.2):

Row LEDs
1 OVER SPEC, LOG, LINK, PS, PCI, SP
2 FAN, TEMP, MEM, NMI
3 CNFG, CPU, VRM, DASD, RAID, BRD

What each LED means (DOCUMENTED, S-004 pp.363-367; Error codes 9.1):

LED Meaning First place to look
(none, system-error LED lit) Undiagnosable error or IMM failure System event log in Setup
BRD System board: battery, missing PCI riser assembly, or failed voltage regulator Board LEDs; CMOS battery; riser in connector 2
CNFG Configuration error, together with CPU or MEM Mismatched CPUs; invalid DIMM population; option ROM out of resources
CPU CPU failed, or invalid CPU configuration with CNFG CPU LEDs on the board
DASD Drive failed or missing Drive status LEDs; backplane
FAN Fan failed, slow or removed (TEMP may also light) LED next to the fan connector
LOG An error was written to the event log IMM and system event logs
MEM Memory error, or invalid configuration with CNFG DIMM LEDs; logs
NMI Non-maskable interrupt System event log
OVER SPEC Shutdown due to overload on a power channel Power-channel LEDs A-E/AUX; supply LEDs
PCI Error on a PCI bus; an LED lights at the failing slot Slot LEDs; remove adapters one at a time
PS Supply failed; PS+CNFG = mixed supply types Supply LEDs
SP IMM failed AC power cycle; IMM firmware
TEMP Temperature over threshold Logs, room temperature, vents, fans
LINK, RAID, VRM Reserved -

The Remind button acknowledges the error: the system-error LED then flashes every 2 s until the problem is fixed, the server restarts or a new problem occurs. The same LED states are visible remotely on the IMM web page "Virtual Light Path". Mapping of IPMI sensors to LEDs: Sensors and SDR 9.

Power-supply LEDs (AC, DC, error) and the components of each 12 V power channel are tabulated in Error codes 9.3 and 9.4. The minimum configuration for the server to start is one CPU in socket 1, one DIMM in slot 3, one power supply, three fans, a riser in connector 2 and the ServeRAID controller (S-004 p.367).

Step 2: the checkpoint code (if the server stops in POST) #

A checkpoint code shows where boot stopped, not what failed (S-004 p.360). Ranges (S-024, generic IBM UEFI): 0x00-0x0F CPU init, 0x10-0x1F PEI, 0x20-0x9E DXE, 0x9F POST complete, 0xA0-0xAF QPI, 0xB0-0xBF memory init, 0xE0-0xE5 processor or bus failure, 0xE8 no memory, 0xED invalid mixed DIMMs, 0xEE invalid DIMM population. A per-code list for this server is UNKNOWN (Error codes 7).

Step 3: POST error codes #

Step 4: IMM event ids #

IMM messages carry an id such as 806f010c-2001xxxx. S-004 lists the ids but not their structure; the decode below is CANDIDATE, inferred from all 655 ids and consistent with the IPMI sensor types measured on the reference unit (Error codes 3):

Field (AABBCCDD-EEFFxxxx) Meaning
AA 80 assertion, 81 deassertion, 40 IMM-internal event
BB IPMI event/reading type: 01 threshold, 03 discrete, 07 generic severity, 0b redundancy, 6f sensor-specific
CC Offset within the type (for thresholds 02 = lower critical going low, 09 = upper critical going high)
DD IPMI sensor type (01 temperature, 02 voltage, 04 fan, 07 processor, 08 power supply, 0c memory, 0d drive slot, 0f firmware, 10 event logging, 23 watchdog)
EE Entity (03 CPU, 04 drive, 07 system board, 0a power supply, 1d fan, 20 DIMM, 22 system firmware, 28 battery)
FF Instance (DIMM n = 20nn, drive n = 04nn)

Worked example: 80010202-2801xxxx = assertion (80), threshold (01), lower critical going low (02), voltage (02), battery entity (28), instance 01: the CMOS battery is below its lower critical threshold. The documented user response is to replace the battery (Hardware 12). The 64 condensed user responses (A01-A64) are in Error codes 5; the full message list in Error codes 4.

Useful IMM-internal ids: 40000023 / 40000024 firmware flash success / failure, 4000002a firmware mismatch, 40000029 SSH login failures; 806f052b-2101xxxx IMM firmware failover; 806f000f-2201xxxx ABR status.

Step 5: the SEL and the IMM event log #

  • The SEL is small (512 entries on the reference unit) and does not overwrite: once full, new hardware events are lost from it. Save it and clear it when the IMM logs the "more than 75 percent full" event (S-004 p.28). POST code 3808004 also reports a full log. Clearing is a state change: ipmitool sel save <file> first, then clear only deliberately.
  • The IMM event log keeps recording while the SEL is full and holds human-readable messages; readlog pages through it five entries at a time. Its capacity was reported as 1500 records on the reference unit (MEASURED).
  • The two logs share a time base but the IMM log is a filtered subset: it omits firmware-progress events, for example (IMM architecture 10).

Step 6: sensors #

ipmitool sensor and ipmitool sdr elist show current readings and thresholds. Threshold names differ between interfaces (IPMI lnc/lcr/lnr, CLI "warning / soft shutdown / hard shutdown"); discrete sensors show state bytes that need the reading-type tables to decode (Sensors and SDR 3, 6). The reference unit's SDR holds 135 sensor records; the full verbose dump with entities, masks and hysteresis is in Sensors and SDR 13. Example thresholds on that unit: ambient warning 38 deg C, soft shutdown 41, hard shutdown 45; Planar VBAT lower critical 2.095 V.

Step 7: DSA Preboot #

Press F2 during POST to start DSA Preboot (stored in IMM flash). Tests end Passed, Failed or Aborted; view results with view in the CLI or the "Diagnostic Event Log" in the GUI. Messages have the form CCC-TTT-xxx: CCC is the component (089 CPU, 166 IMM I2C, 201/202 memory, 215 optical, 217 SAS/SATA drive, 405 Broadcom Ethernet ...), TTT 8xx = aborted, 9xx = failed (CANDIDATE from the state column); each maps to an action D01-D28 (Error codes 10, 11). DSA Portable runs the same inventory from a supported OS (tools guide).

Good practice drawn from the documents #

  • Read before changing: logs, LEDs and sensors are all readable without side effects; clearing a log, resetting the IMM or reseating parts is not.
  • After installing or removing a DIMM, disconnect power and wait 10 seconds before restarting (S-004).
  • Before replacing the CMOS battery, record UEFI settings (ASU save), because they may be lost.
  • Check for a newer firmware level or a RETAIN tip when an action says so; IBM's actions often start with "update the firmware" (see the firmware guide for what that involves).
