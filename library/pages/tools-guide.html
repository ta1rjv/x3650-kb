Tools Guide

The management, diagnostic and update tools of the x3650 M3 era - ASU, DSA, UXSPI, BoMC, OneCLI, iflash, ipmitool, StorCLI, SAS2IRCU/SAS2FLASH - what each is for, how it reaches the hardware, and which commands only read and which change state.

IBM shipped the x3650 M3 with the "ToolsCenter" family of utilities; Lenovo later replaced most of them with OneCLI. This guide explains what each tool is for, which transport it uses, which operating systems it supports, and - most importantly - which commands only read and which change the machine. The detail, local package paths and hashes are in the Tools volume.

Conventions: read-only = the command reads state (it may write a local output file); STATE-CHANGING = it changes settings, firmware, logs, power or the host's own network. Command syntax below is DOCUMENTED unless marked CANDIDATE. Placeholders such as <IMM_IP> stand for your own values; never put passwords on a command line.

Transports first #

Most confusion with these tools comes from how they reach the IMM (Tools 3):

Transport Used by Notes
KCS (in-band IPMI, /dev/ipmi0) ipmitool, ASU (--kcs or fallback), iflash (--kcs) "The local connection over the KCS interface does not require authentication" (S-026): any root process can talk to the IMM
LAN over USB (IMM at 169.254.95.118) ASU (default), DSA, UXSPI, BoMC media, iflash packages The tools may configure the host's USB network interface and routes themselves (IBM's cdc_interface.sh); IBM readmes warn about duplicate 169.254.x addresses and cluster software
IMM external LAN ASU --host, ipmitool -I lanplus, web, SSH CLI, SNMP, CIM Works with the host OS down; needs IMM credentials
Bootable media Preboot DSA, BoMC images Runs on the server instead of its OS; needs a reboot

Practical rule drawn from the volume: an in-band tool run that touches LAN over USB should be treated as STATE-CHANGING for the host's networking (CANDIDATE), which is why --kcs is used for read-only ASU work.

ASU - Advanced Settings Utility #

Purpose. ASU reads and writes every setting that UEFI exposes through its setup XML (uEFI.*, iSCSI.*, PXE.*) and the IMM settings (IMM.*), saves and restores whole configurations, manages IMM certificates and has an immapp helper for power state and logs (S-026). Version 3.0.0 or later is required for the IMM (S-020); the newest local copy is ASU 10.3 (Lenovo package DS118233). Setting names and defaults: UEFI guide, UEFI Appendix A.

Connection options (S-026 printed pp.16-17): no option = LAN over USB with default settings, then KCS; --kcs = KCS only, no authentication; --host <IMM_IP> with credentials = out-of-band over the IMM LAN.

Read-only:

asu64 show all --kcs                     # every setting
asu64 show uEFI.OperatingMode --kcs      # one setting
asu64 showvalues uEFI.OperatingMode --kcs
asu64 showdefault uEFI --kcs
asu64 comparedefault uEFI --kcs
asu64 save <local_file> --kcs            # writes a local file only
asu64 immapp powerstate --kcs
asu64 immapp showsel --kcs

STATE-CHANGING:

asu64 set <setting> <value> --kcs        # applies at the next boot for uEFI settings
asu64 loaddefault uEFI --kcs             # does not reset the boot order on IMM systems
asu64 restore <file> --kcs | replicate <file> --kcs | batch <file> --kcs
asu64 set IMM.LanOverUsb Disabled --kcs  # documented to need --kcs, the link drops during the set
asu64 rebootimm --kcs                    # IMM restart
asu64 immapp poweronos|poweroffos|rebootos --kcs
asu64 immapp clearsel|clearimmlog|clearalllog --kcs

Caveats (DOCUMENTED, Tools 4.6): after changing settings with ASU on an IMM system, reset the IMM before flashing firmware or the changes may be lost; some settings need an IMM restart; BIOS-only commands (dump, readraw, writeraw) do not apply to this UEFI server.

DSA - Dynamic System Analysis #

Purpose. DSA collects configuration, installed software, hardware inventory, light path status, service processor configuration, VPD and firmware levels, drive health, RAID configuration and the OS, RAID and IMM event logs into one compressed XML (with optional HTML), and runs non-destructive diagnostics (S-028; DSA 10.1 readme).

Editions. Preboot is embedded in IMM flash and started with F2 at POST (or booted from media); the newest package is 9.53 DSYTC5F (Tools 5.7). Portable is a self-extracting executable (newest local 10.1 DSALA5Q) built only for RHEL, SLES, VMware 4.x and Windows; its behaviour on other distributions is UNKNOWN.

<dsa-package> -x -v -d <out_dir> --no-imm-lan   # read-only collection (runs vendor code as root)
<dsa-package> -diags --no-imm-lan               # non-destructive diagnostics; still loads the server
<dsa-package> -v -x -i <file>.xml.gz            # render an existing collection offline
<dsa-package> -v                                # without --no-imm-lan: may reconfigure LAN over USB and routes
<dsa-package> -t | -upload | --update           # network transfers to the vendor or FTP

Caveats: collections contain serial numbers and configuration, review before sharing; without --no-imm-lan the readme warns that 169.254.95.x route changes can crash cluster software (Tools 5.6). DSA messages are decoded in the troubleshooting guide.

UXSPI, BoMC and OneCLI #

  • UXSPI (UpdateXpress System Pack Installer) applies UpdateXpress System Packs and individual updates; commands compare (read-only inventory), acquire (download), update (STATE-CHANGING). It supports RHEL 4-7, SLES 10/11 and Windows; --remote works only OS-to-OS of the same type. IBM names UXSPI and BoMC the preferred update tools for IMMv1 systems (S-022, S-029) (Tools 6).
  • BoMC (Bootable Media Creator) builds one bootable CD, DVD, ISO, USB or PXE image with Preboot DSA, UXSPI and the update packages for selected machine types. Creating media touches no server; booting it on the server is STATE-CHANGING. Media need UEFI or UEFI-and-legacy boot mode; BoMC needs LAN over USB enabled to compare levels (S-030; BoMC readmes) (Tools 7).
  • OneCLI (Lenovo XClarity Essentials) replaces ASU, DSA and UXSPI on Lenovo systems. No OneCLI package appears in the Lenovo catalog for machine type 7945; support for IMM v1 is UNKNOWN. In-band it documents creating a temporary BMC account over KCS (CANDIDATE reading: state-changing) (Tools 8).

iflash #

Every IBM IMM, UEFI and DSA package carries iflash (i386) and iflash64 (x86-64) inside its image.zip, started by the linwrap wrapper. Options (package readme): --package, --user, --password / --password-file, --unattended, --force, --backup (secondary bank), --no-reboot, --skip_min_level, --silent; strings also show --kcs, --tftp and --disable-imm-lan (EXTRACTED). Running a package with -x <dir> only extracts it, but it still executes the vendor wrapper; scripts/ibm_fw_unpack.py extract extracts without running anything. Every flash is STATE-CHANGING (Tools 9, Firmware formats 8).

ipmitool #

The generic IPMI client works in-band (OpenIPMI driver, /dev/ipmi0) and out-of-band (-I lanplus, RMCP+ on 623/udp) (Tools 12).

Read-only:

ipmitool mc info              ipmitool fru print           ipmitool sdr elist full
ipmitool sdr type list        ipmitool sensor              ipmitool sel info
ipmitool sel elist            ipmitool chassis status      ipmitool lan print 1
ipmitool channel info 1       ipmitool user list 1         ipmitool sol info 1
ipmitool mc getenables        ipmitool mc guid             ipmitool sel save <file>
ipmitool -I lanplus -H <IMM_IP> -U <user> -f <password_file> sdr elist full

STATE-CHANGING:

ipmitool chassis power off|on|cycle|reset|soft
ipmitool chassis bootdev <device>
ipmitool chassis policy always-on|previous|always-off
ipmitool sel clear
ipmitool mc reset warm|cold          # IMM restart, up to 17-20 minutes
ipmitool lan set 1 ...               # can cut out-of-band access
ipmitool user set|enable|disable|priv ...
ipmitool sensor thresh <sensor> ...
ipmitool sol activate                # opens the console session
ipmitool raw <netfn> <cmd> ...       # treat as state-changing unless known to be a read

Not implemented by IMM v1 (MEASURED): mc getsysinfo and dcmi discover return "Invalid command". Use -f <file> or -E rather than -P <password>, which exposes the password in the process list (CANDIDATE good practice).

StorCLI, SAS2IRCU and SAS2FLASH #

StorCLI manages MegaRAID controllers including the ServeRAID M1015 (Lenovo packages up to 1.16.14; the readme lists the M1015 46M0831). The storcli64 binary is static x86-64 and ran read-only from a temporary copy on the reference unit (MEASURED). Read-only: storcli64 show, /c0 show all, /c0/vall show all, /c0/eall/sall show all, /c0 show patrolread, /c0 show cc, /c0 show eventloginfo, /c0/fall show. STATE-CHANGING: add vd, del, set on controllers, VDs or drives, foreign import, and download file= (firmware) (Tools 10). WebBIOS (Ctrl+H, or the UEFI HII browser on UEFI boots) and MegaRAID Storage Manager are the interactive alternatives (Storage 8).

SAS2IRCU 20.00.00.00 is the IR/volume utility for LSI SAS2 HBAs; its readme lists the "6Gb SAS HBA (46M0907)" and requires the mpt2sas module. The binary is static i386. Read-only LIST, 0 DISPLAY, 0 STATUS and state-changing CREATE, DELETE, HOTSPARE, LOCATE follow common LSI usage and are CANDIDATE syntax only. SAS2FLASH (the SAS2 firmware flasher) has no standalone package in the repository; version 20.00.00.00 is bundled inside the IBM HBA 1.20 package, where its strings refuse to flash IT over IR firmware (and the reverse) and refuse NVDATA downgrades (EXTRACTED; -listall is its read-only listing, every flash is STATE-CHANGING) (Tools 11, Storage 7.1).

The project's own scripts #

The repository adds offline analysis tools, all Python 3 standard library only (Tools 14; listed in the Catalogs section):

Script What it does Touches a server?
scripts/ibm_fw_unpack.py Unpacks IBM PKG SDK packages, .upd images and descriptors; UEFI volumes, microcode, HII forms and strings; package diff no (offline, never executes package content)
scripts/uefi_fv.py UEFI PI firmware volume, FFS file and section parser (list, extract, diff, microcode) no
scripts/imm_upd.py Parser for IMM v1 .upd images: tar, uImage, big-endian JFFS2 extraction no
scripts/lenovo_downloads.py Lenovo download catalog and verified fetcher for machine type 7945 no (vendor website only)
scripts/wayback_mirror.py Mirrors the retired x3650 M3 infocenter from the Internet Archive no
scripts/imm_wsman_read_inventory.py Calls only parameterless WS-Man "Get" operations of an IMM and redacts secrets read-only, IMM
scripts/imm_cim_read_inventory.py CIM-XML class and instance enumeration of an IMM, with redaction read-only, IMM
scripts/vzdump-verify-prune.sh Backup hook for a hypervisor host: deletes older backups only after the new one verifies host only

Tests for all scripts run with python3 -m unittest discover -s tests -v.
