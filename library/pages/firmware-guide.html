Firmware Guide

Every firmware component of the x3650 M3 (IMM, UEFI, DSA Preboot, ServeRAID M1015, 6Gb SAS HBA, BCM5709) - versions, latest levels, package formats, how updates are delivered and the documented risks.

The x3650 M3 carries six independently updated firmware images that matter in practice. This guide explains what each one is, which versions exist, how IBM packaged them, how an update reaches the hardware and what the vendor documents warn about. It describes; it does not recommend an update for any particular machine. The authoritative detail is in the volumes linked in each section, chiefly Firmware history, Firmware formats and the firmware update plan (a PLANNED, never executed plan for the reference unit, useful as a worked example).

No FPGA, backplane or power-supply firmware package exists for this machine type in the sources searched; IBM's IMMv1 best-practice guide mentions an FPGA only for X5-class systems (Firmware history, latest). Drive firmware for the 2.5-inch drives is not in the repository (UNKNOWN).

IMM v1 #

Versions. IMM v1 releases run from 1.00 (YUOO18D) to 1.55 (YUOOH5A); there is no 1.13, 1.15 or 1.23 in the changelog. Milestones from the vendor changelog (DOCUMENTED):

Version Build Why it matters
1.10 YUOO57H First level supporting the x3550 M3 / x3650 M3; SSH enabled by default. Minimum level from which 1.30 may be installed.
1.12 YUOO67C DC power-supply support for M3 systems
1.14 YUOO73M Performance-mode fan control, M3 power-reading accuracy; required before UEFI 1.08
1.22 YUOO84C IPv6; a downgrade below 1.22 requires a reset to factory defaults
1.30 YUOOC7E SSL fix; 64-bit ActiveX remote control
1.32 YUOOD4G SSH-versus-web lockout bypass fixed; every service port can be enabled or disabled
1.33 YUOOE3C Fixes the 1.30-1.32 unexpected-reset and failover defect (RETAIN H206034, see risks)
1.40 YUOOF7A Automatic failover to the backup bank on firmware corruption
1.42 YUOOG2C SHA256/SHA512 support
1.44-1.53 YUOOG6C-YUOOH4B OpenSSL and TLS fixes: CVE-2014-0224/0076, POODLE CVE-2014-3566, Logjam CVE-2015-4000, OpenSSL 1.0.2d (1.50), security headers and TLS 1.2-only high-security mode (1.53)
1.55 YUOOH5A OpenSLP heap memory corruption (CVE-2017-17833 per the security bulletin); image dated 2018-01-16

The complete list and the interface-relevant changes are in IMM interfaces 13 and IMM architecture 9.4.

Package format (EXTRACTED). The delivery file (ibm_fw_imm_yuooXXX-1.NN_linux_32-64.bin or .exe) is an IBM "PKG SDK" self-extractor. Inside is imm_yuooXXX.upd, a GNU tar holding a descriptor (ibmc.xml, format IBMBladeCenterFWUpdFmt) and ibmc.tgz with u-boot.bin, uImage (big-endian MIPS Linux 2.6.16.46), rootfs.jffs2 and bootfs.jffs2. Integrity is checked with MD5 and CRC32; no firmware signature was found in either 1.10 or 1.55 (Firmware formats 7, 7.9). The 1.55 package also ships the host flashers iflash/iflash64 (v1.12.28) and the IMM MIB files.

Banks. The IMM has a primary and a backup firmware page. On the flash, IMM 1.10 keeps two UBI "sides" for kernel, root and boot file systems; an update writes the inactive side (EXTRACTED; applicability to other levels CANDIDATE). Jumper J147 pins 2-3 boots the backup page (DOCUMENTED, S-004 Table 4) (IMM architecture 3.2).

UEFI #

Versions. UEFI releases run from 1.00 (D6E123A) to 1.22 (D6E164A). Milestones (DOCUMENTED, UEFI 1.22 changelog and UXSP pages):

Version Build Why it matters
1.02 D6E126A Power-profile setup option
1.06 D6E145C Xeon 5600 (Westmere-EP) support; the minimum UEFI level recorded in SMBIOS on the reference unit
1.08 D6E148B Data errors on LUNs above 2 TB fixed; requires IMM YUOO73M (1.14) first
1.09 D6E149C Xeon 5600 C6 false memory errors fixed
1.12 / 1.15 D6E153A / D6E157A IPv6 and POST Attempts Limit; Limit Boot Attempts and IMM VLAN ID
1.13 D6E154B in the 1.22 changelog; D6E154A in the 1.13 package readme Conflict recorded: the 1.13 package, SMBIOS, NVRAM and the IMM of the reference unit all say D6E154A = 1.13
1.17 D6E159A Intel MRC 2.50; C2/C3 ACPI C-state fix
1.18 D6E160A Microcode for errata BD131/BD132/AAK167
1.21 D6E163A Spectre v2 microcode (CVE-2017-5715)
1.22 D6E164A Speculative Store Bypass microcode (CVE-2018-3639/3640); package dated 2018-06-04 (descriptor) / 2018-07 (download page)

Package format (EXTRACTED). Same PKG SDK wrapper. The .upd holds oem_ibm.xml and a tarball of five images: Capsule_P.scap (early boot code with an RSA2048-SHA256 signature trailer), FvPlatform.fv, FvDxe.fv, FvOem_Ibm.fv (carries the setup XML used by ASU) and FvMicrocode.fv; 178 modules in 1.13, 1.14 and 1.22 (Firmware formats 5, 6).

What 1.22 changes against 1.13 (EXTRACTED). 154 of 178 modules differ; microcode for CPUID 0x206C2 moves from revision 0x14 to 0x1F; new setup options appear (IMM VLAN, Limit Boot Attempts, Memory Refresh, Static Driver Impedance) and the default C-state limit changes from ACPI C3 to C2 (UEFI 8.1, UEFI 9). More in the UEFI guide.

DSA Preboot #

DSA Preboot is a Linux-based diagnostic environment stored on an IMM staging volume and launched with F2 during POST. The 9.53 package (DSYTC5F) is a PKG SDK self-extractor whose .upd contains a 98.5 MB boot image (pdsa, a FAT file system) with firmware_type dsa, device_type imm1; the boot kernel, initrd and root file system inside are dated 2011-07-08 while the DSA payload is dated 2014-02-17 (EXTRACTED). The 3.48 to 9.53 changelog lists new systems, tests and "several CVEs" without naming any x3650 M3-specific fix (Tools 5.7).

ServeRAID M1015 (M1000 series) #

The IBM package "ServeRAID M1000 Series SAS/SATA Controller Firmware Update" (ibm_fw_sraidmr_1000-...) covers the M1015 (46M0831) and M1115. Versions after 20.10.1-0052 fix wrong drive LED blinking, intermittent RAID key failure, configurations going foreign after a key failure, failed auto-rebuild after drive replacement, drives reporting 65 C and NULL event-log entries (DOCUMENTED, UXSP changelog). Packages 20.11.1-0184 and 20.13.1-0254 are held by the project. The M5000-series package (12.15.0-0248) is for M5014/M5015/M5025 and does not support the M1015 (Storage 7).

IBM 6Gb SAS HBA #

Package "IBM HBA 6Gb Controllers BIOS/FW/UEFI Update" 1.20 bundles IOC firmware 20.00.02.00 in IT personality for subsystem 03ca (the IBM 6Gb SAS HBA, option 46M0907) and 03cb, the legacy BIOS 7.39.00.00 and the UEFI BSD driver 7.27.04.00; the flash wrapper maps subsystem IDs to images (EXTRACTED). The installer refuses distributions other than RHEL/SLES, and sas2flash refuses downgrades ("Cannot downgrade NVDATA") (Storage 7.1). The IT-versus-IR distinction is explained in the glossary.

Broadcom NetXtreme II BCM5709 #

The NIC package (brcm_fw_nic_2.x.yz_linux_32-64.bin) uses the same wrapper with an empty image.tar; the payload runs fwuplnx, which flashes in-band through the bnx2 driver while the OS is running and updates only if the installed level is lower. Between 2.1.5b and 2.4.1c bootcode goes 5.2.2 to 7.4.0 and NC-SI 2.0.10 to 2.0.13; no 5709 security fix is documented. The tool has options that disable management firmware or NC-SI (-nomfw, -ncsidisable), which would cut an IMM link shared over Ethernet 1 (CANDIDATE) (Firmware formats 12.5).

Package formats in one picture #

Every IBM package of this era follows the same pattern (EXTRACTED, Firmware formats 3, 4):

File Role
<name>.bin / <name>.exe PKG SDK self-extractor: ELF i386 (Linux) or PE32 (Windows) stub + unzip + image.tar (the .upd) + image.zip (flash tools, wrapper scripts) + imgboot.cfg, located by a 20-byte trailer of five little-endian sizes
<name>.xml CIM-XML descriptor (supported machine types, prerequisites, CRC, release date) used by UpdateXpress
<name>.chg Change history
<name>.txt Readme: install methods, prerequisites, known issues
<build>.upd Flash payload: tar with a descriptor (oem_ibm.xml, ibmc.xml or dsap.xml) and the images

Packages can be unpacked without running them, either with -x <dir> on the vendor wrapper (executes vendor code) or statically with scripts/ibm_fw_unpack.py extract (reads bytes only) (Firmware formats 9).

How updates work #

Delivery paths (DOCUMENTED).

Path Applies to Notes
UpdateXpress System Pack Installer (UXSPI) or Bootable Media Creator (BoMC) all IBM's preferred method (S-022 p.6); UXSPI runs on Windows, RHEL, SLES
IMM web interface, Tasks -> Firmware Update IMM, UEFI, DSA Out-of-band, OS independent; restart the IMM after an IMM update; UEFI and DSA need the server powered on
IMM CLI update -i <tftp server> -l <file> IMM-held images TFTP based; needs advanced adapter configuration authority (S-020 p.153)
Individual package run in the OS (.bin -s, iflash) IMM, UEFI, DSA In-band over LAN over USB (or KCS with --kcs); Linux packages support RHEL/SLES only
Package run in the OS (fwuplnx, sas2flash, MegaRAID tools) NIC, HBA, RAID In-band through the device driver

Order. IMM first, then UEFI, then DSA Preboot (IMM 1.55 readme 1.4; S-022 pp.11-12). UEFI and DSA updates need IMM 1.07 or later per the readme (the changelog header says 1.14; recorded conflict). An update to IMM 1.30 requires 1.10 or later as the starting level (IMM architecture 9.1, Firmware history, update order).

In-band mechanism (DOCUMENTED, S-025; confirmed EXTRACTED). The package brings up the LAN-over-USB link (IMM at 169.254.95.118), finds the IMM by SLP if needed, asks it to start an embedded FTP server, uploads the image, polls the status and lets the IMM write the image; the IMM reboots itself after an IMM update. On the IMM side a flash manager checks firmware type, build ID and sizes, then writes the inactive side (IMM architecture 9.3).

Durations. The IMM runs a full operating system and can need up to 17 minutes after an update before it is ready; the first restart after an IMM update can take up to 20 minutes (S-022 pp.7, 12). Updates through BoMC, UXSPI or in-band packages take at least 17 minutes (S-022 p.9).

Backup bank. iflash --backup targets the secondary bank ("if available"; the IMM may ignore the option) (Firmware formats 8).

Documented risks #

These are warnings that appear in vendor documents or follow directly from the analysis. They apply to any x3650 M3 and are listed so that a reader can judge an update; the library does not tell anyone to update.

Risk Statement Level and source
IMM 1.30-1.32 failover defect IMM 1.30, 1.31 and 1.32 can reset unexpectedly, fail over to the alternate bank and stop working if that bank does not initialise; AC cycling does not recover it; fixed in 1.33. The tip lists BladeCenter HX5 and x3690/x3850/x3950 X5 only, so applicability to the x3650 M3 is CANDIDATE DOCUMENTED (IBM RETAIN tip H206034), IMM architecture 3.2
Mixed IMM banks A firmware architecture change from Q3 2011 makes mixed-bank images unpredictable DOCUMENTED (IBM support node 860842), Firmware history
C-state erratum Command-line updates on 32-bit Linux (readme) or Linux and VMware (S-022) can be affected by an Intel C-state erratum; web, BoMC and AMM updates are not DOCUMENTED, IMM architecture 9.1
Secure Region Update Never power off while "Secure Region Update in Progress" is shown (the CRTM update after a UEFI update) DOCUMENTED (S-022 p.10)
IMM downgrades Going below 1.22 needs a factory reset; 1.09 to 1.10 enforces password rules; crossing 1.05 reverts alert e-mail and DST settings; going below 1.07 needs AC removal before a reboot DOCUMENTED (changelog, readme, S-022)
UEFI backup bank Updating the UEFI backup firmware with the IMM32F method may fail DOCUMENTED (RETAIN H196209, S-022 pp.15-16)
New UEFI defaults New setup options take their defaults after an update (for example Limit Boot Attempts defaults to Enable in 1.22) EXTRACTED, UEFI 7
ASU changes before flashing After changing settings with ASU on an IMM system, reset the IMM before flashing, or the changes may be lost DOCUMENTED (S-026), Tools 4.6
M1015 rollback The 20.13 readme verifies rollback only to a few named levels; the RAID controller carries the boot volume on many systems DOCUMENTED, update plan 4
Wrong RAID package The M5000-series package does not support the M1015; rolling M5000 back to 12.7 or earlier stops the controller DOCUMENTED, Storage 7
HBA downgrade Downgrades are not supported; sas2flash refuses an NVDATA downgrade DOCUMENTED / EXTRACTED, Storage 7.1
Shared NIC NIC update options that disable management firmware or NC-SI can cut a shared IMM connection CANDIDATE, Firmware formats 12.5
Host OS IBM Linux packages install only on RHEL/SLES; on other distributions use the IMM web interface or bootable media DOCUMENTED / CANDIDATE, update plan 2
Weak CMOS battery A depleted battery loses UEFI settings and the clock when AC is removed; save settings first DOCUMENTED, Hardware 12
Full SEL When the SEL is full, new entries are not written, so flash success or failure events would be missing DOCUMENTED (S-004 p.28)

Recovery features #

Feature How it works Source
UEFI ABR If the IMM detects a bad primary UEFI bank during start it boots the backup bank (POST 3048006); after repairing the primary, press F3 at "Press F3 to restore to primary" or remove AC for 15 s DOCUMENTED (S-004 p.375, S-024 p.18), Error codes 13
J29 UEFI boot recovery jumper; pins 2-3 load the backup UEFI page; change only with power off DOCUMENTED (S-004 Table 4), UEFI 3
J147 IMM recovery jumper; pins 2-3 load the backup IMM page DOCUMENTED (S-004 Table 4)
IMM automatic failover From IMM 1.40 the IMM fails over to the backup bank on corruption DOCUMENTED (changelog)
Nx boot failure After 3, 6 or 9 failed POST attempts the server loads default settings and enters Setup DOCUMENTED (S-004 p.375)

Where the packages are #

The project holds the IBM packages under firmware/ibm/ (IMM 1.30 changelog and readme; IMM 1.55; UEFI 1.13, 1.14 and 1.22; DSA 9.53; M1015 20.11.1-0184 and 20.13.1-0254; M5000 12.15.0-0248; HBA 1.20 and H1110 1.20.02; Broadcom 2.1.5b, 2.3.1e readme and 2.4.1c; UXSP pages) and Lenovo catalog downloads under firmware/lenovo/. Download origins are recorded in firmware/ibm/SOURCE.txt. The public library lists names, versions and hashes in its Catalogs section; it does not redistribute the binaries.
