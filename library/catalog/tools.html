build_library.py #

Build the public static "library" website of the x3650m3-kb repository (GitHub Pages).

Usage:
  python3 scripts/build_library.py --out _site [--repo .] [--config site/publish.json] [--strict-links]

Dependency: Python-Markdown (pinned in requirements-site.txt); everything else is the standard library.

Output: OUT/index.html (redirect to library/), OUT/library/index.html (home shelf) and every page below
OUT/library/. All links are relative, so the site works under /x3650m3-kb/ on GitHub Pages and from file://.
No external fonts, scripts or stylesheets are referenced.

Inputs (repository paths):
  docs/X3650M3_*.md          knowledge volumes (except the never-published list in site/publish.json)
  publish.json about_docs    selected project documents ("About this project")
  site/pages/*.md            hand-written pages with front matter (title, section, order, summary)
  firmware/**/SHA256SUMS     firmware package catalog (metadata only, binaries are never published)
  firmware/ibm/SOURCE.txt    download origin, installed and latest markers of the IBM packages
  sources/SOURCES.md         source document catalog (S-xxx ids); sources/lenovo/CATALOG.md summary
  scripts/*.py, scripts/*.sh tools reference (parsed with ast, never imported or executed)
  git ls-files + site/catalog/files.tsv   repository file index (path<TAB>description, longest prefix)

Publication safety: every string that reaches the output passes through scripts/library_sanitize.py with
the rules of site/publish.json. After the build the leak gate scans every output file; on any finding the
output directory is deleted and the exit status is 1 (fail closed). Exit status 2 = usage, configuration
or input error.

ibm_fw_unpack.py #

Offline analysis of IBM System x firmware update packages (x3650 M3 era).

Python 3 standard library only. The tool never executes anything contained in a
package; it only reads bytes and writes extracted copies to an output directory.

Supported formats (see docs/X3650M3_FIRMWARE_FORMATS.md):
  * IBM "PKG SDK" self-extractors (.bin = ELF i386 stub, .exe = PE32 stub) with
    a 20-byte trailer of five little-endian uint32 element sizes:
      [stub, unzip utility, image.tar (.upd), image.zip, imgboot.cfg]
  * The .upd update image (POSIX tar: oem_ibm.xml + <build>.tar.gz)
  * The CIM-XML package descriptor (.xml, class IBMPSG_SystemUpdateElement)
  * UEFI PI firmware volumes (FFS v2), EFI/Tiano and LZMA compressed sections,
    Intel microcode updates, PCI option ROMs, HII string and form packages.

Sub-commands:
  info      identify a package and list its elements (JSON)
  extract   extract all elements of a package into a directory
  xml       parse a CIM-XML package descriptor into JSON
  upd       parse a .upd image (tar with oem_ibm.xml) into JSON
  fv        list firmware volumes / FFS files of a file
  microcode list Intel microcode updates found in a file
  hii       dump HII string packages and the reconstructed setup form tree
  baseline  write a text fingerprint of a UEFI package into a directory
  diff      compare two baseline directories

imm_upd.py #

Offline parser for IBM IMM v1 firmware update images (.upd, "YUOO" builds).

Python 3 standard library only. The tool never executes anything contained in an
image; it only reads bytes and, for `jffs2 --outdir`, writes copies of regular
files (mode 0644, no symlinks or device nodes) into an output directory.

Format (EXTRACTED from IMM 1.10 YUOO57H / YUOO57X, see
docs/X3650M3_FIRMWARE_FORMATS.md section 7):
  * outer GNU tar: ibmc.xml (IBMBladeCenterFWUpdFmt descriptor) + ibmc.tgz
  * ibmc.tgz: gzip tar with u-boot.bin, uImage (U-Boot legacy image, MIPS
    Linux), rootfs.jffs2 and bootfs.jffs2 (big-endian JFFS2)
  * integrity: XML <md5chk> = MD5 of ibmc.tgz, <compressed_size> = size of the
    .upd file in YUOO57H (YUOO57X_v2 is one 10240-byte tar record larger),
    gzip CRC32, uImage header/data CRC32, JFFS2 node CRCs; no signature block
    was found.

Sub-commands:
  info   parse a .upd and verify md5chk, compressed_size, uImage CRCs, JFFS2 (JSON)
  jffs2  list (and optionally copy out) the regular files of a JFFS2 image

lenovo_downloads.py #

Lenovo Data Center Support download catalog and fetcher for machine type 7945.

Commands:
  catalog  Fetch (or read a saved) driver-list API response and write a normalized
           catalog JSON plus a human-readable CATALOG.md.
  fetch    Download catalog files into <dest>/<category-slug>/<DocId>/<filename>,
           verify hashes, write SHA256SUMS and SOURCE.txt per DocId directory.
  status   Report present / missing / bad files per category.

Python 3 standard library only.

API notes (verified 2026-10-19):
  - The API answers 403 {"message":"deny access"} without a session. A GET of the
    HTML driver-list page with a browser User-Agent sets the cookies the API needs;
    the API call then needs Referer = page URL, Accept: application/json and
    X-Requested-With: XMLHttpRequest.
  - download.lenovo.com and delivery04.dhe.ibm.com files download without cookies.
  - "Size" values are rounded display strings ("323.79 MB"); they are not exact and
    are never used for verification. Units are interpreted as binary (1 KB = 1024 B),
    which is an assumption.
  - Many files (mostly old delivery04.dhe.ibm.com entries) carry no hash at all.
  - Some URLs carry a signed, expiring "__token__" query parameter (Microsoft OEM
    media). The token is removed from the catalog and such files are not fetched.

library_sanitize.py #

Sanitizer and leak gate for the public x3650m3-kb library site - Python 3 standard library only.

The repository is private, the GitHub Pages library built from it is public. Every piece of text that
goes into the site (rendered pages, search index, catalogs, file names) passes through this module, and
the finished output tree is scanned by the leak gate before it may be published.

Rules come from site/publish.json (see that file for the active rule set):
  remove_sections  Whole sections (heading plus everything up to the next heading of the same or a higher
                 level) of a named document: [{"file": "X3650M3_FOO.md", "heading": "11. Exact heading"}].
                 A configured section that is not found is reported by missing_sections() (no silent drift).
  remove_blocks  Markdown blocks (paragraph, list item with its children, table row, heading, code fence)
                 that match any of these patterns are dropped completely (embedded firmware credentials,
                 live-server security findings). A rule with "require" removes a block only when the block
                 also matches the require pattern (e.g. only MEASURED statements, not vendor documentation).
                 With "scope": "sentence" only the matching sentences of a paragraph are dropped, a
                 matching list item is dropped whole (items are single facts), and in a table row only the
                 matching cells are replaced by removed_text (the row goes when its first cell matches).
  finding_refs   References to security review finding IDs are replaced by a fixed text.
  identifiers    Literal owner identifiers (serial numbers, UUIDs, WWNs ...). Matched case-insensitively,
                 tolerant of "-", ":" or " " between characters, replaced by one token.
  redact         Regex rules (lab IP ranges, lab host names, MAC addresses, host paths, credential file
                 names, Proxmox guest IDs) with their replacement text.
  forbidden      Extra leak-gate patterns. The gate also checks every identifier, redact, remove_blocks and
                 finding_refs pattern, so nothing a rule should have caught can survive unnoticed.

Markdown sanitizing replaces matches by letter-only placeholder tokens first (they cannot be mistaken
for Markdown syntax) and finalize() turns the tokens into the display text after rendering.

Commands:
  scan DIR   Run the leak gate over every file below DIR; print file:line:rule for each finding.
             Exit status 0 = clean, 1 = findings, 2 = configuration or usage error.
  text FILE  Print the sanitized Markdown of FILE (finalized) for manual review.

uefi_fv.py #

UEFI firmware volume (FV), FFS file and section parser - Python 3 standard library only.

Built for the IBM System x3650 M3 UEFI images (D6E1xx builds), but follows the UEFI
Platform Initialization (PI) specification structures, so it works on other PI images.

Commands:
  list     Parse one or more files (raw FV, capsule, or any blob that contains FVs) and
           print every volume, file and leaf section (GUID, type, UI name, sizes, SHA256).
  extract  Write every leaf section body (PE32, TE, RAW, UI, ...) and every RAW file to a
           new, empty output directory. Nothing is ever executed.
  diff     Compare two images (or two directories of .fv/.scap files) module by module.
  microcode  List Intel microcode updates found in RAW files.

Input handling:
  - FVs are located by scanning for the "_FVH" signature at offset 0x28 of a candidate
    header and validating the header checksum, so capsules (.scap), whole flash dumps
    and single .fv files are all accepted.
  - A directory argument means "all *.fv and *.scap files in it, sorted by name".

Decompression:
  - Compression section type 1 (EFI_STANDARD_COMPRESSION): the EFI (position bits 4)
    and Tiano (position bits 5) variants are both implemented here in pure Python; the
    variant whose output parses as a valid section stream is used and reported.
  - GUID-defined sections: CRC32 (FC1BCDB0-...) is unwrapped; LZMA (EE4E5898-...) is
    decoded with the stdlib lzma module; Tiano (A31280AD-...) with the decoder here.
  - Anything else is reported as opaque; nothing is guessed.

Safety: input files are treated as untrusted data. The parser bounds every length
against the containing buffer, limits recursion depth and decompressed size, and only
writes into the output directory given on the command line.

vzdump-verify-prune.sh #

vzdump-verify-prune.sh - Proxmox VE vzdump hook script.

Retention rule: keep exactly ONE backup per guest on the backup storage.
The previous backup of a guest is deleted only after the new backup of
that guest has been written AND verified. Built-in vzdump pruning is
expected to be disabled (prune-backups keep-all=1).

Install (on the PVE host):
  install -m 0755 vzdump-verify-prune.sh /usr/local/bin/vzdump-verify-prune.sh

wayback_mirror.py #

Mirror retired Eclipse-infocenter topics from the Internet Archive (Wayback Machine).

Built for the Lenovo System x infocenter (https://systemx.lenovofiles.com/help/),
whose live host no longer answers. Default target: the System x3650 M3 plugin
(machine type 7945, Lenovo and older IBM plugin ids).

Commands:
  mirror    Enumerate captures via the CDX API, fetch the newest usable 200 capture
            of every page (raw, "id_" form, no Wayback toolbar), follow links inside
            fetched pages to find pages CDX did not list, optionally fetch referenced
            images, then rebuild text/, MANIFEST.tsv and INDEX.md. Resumable: pages
            already saved and listed in MANIFEST.tsv are skipped.
  text      Rebuild text/, MANIFEST.tsv titles/hashes and INDEX.md offline from the
            saved HTML (no network).
  plugins   List plugin ids seen in CDX under the host prefix, optionally filtered
            by a regular expression (e.g. "imm|7945|4255|7949|7376").

Output layout (default --out sources/infocenter/7945):
  html/<page>.html     raw archived topic HTML as served by Wayback "id_"
  text/<page>.txt      ASCII plain text (headings kept, tables as pipe rows)
  images/<file>        images referenced by the pages (unless --no-images)
  MANIFEST.tsv         page, original URL, snapshot timestamp, sha256, title
  IMAGES.tsv           file, original URL, snapshot timestamp, sha256
  FAILED.tsv           pages that could not be retrieved, with the reason
  CDX.tsv              CDX records used for enumeration (evidence)
  INDEX.md             pages grouped by prefix, with titles and counts

Facts used (verified 2026-10-19):
  - CDX API: http://web.archive.org/cdx/search/cdx (space separated rows).
  - Raw capture: http://web.archive.org/web/<timestamp>id_/<original>; Wayback
    redirects to the nearest capture when the exact timestamp does not exist.
  - Topics are archived as help/topic/<plugin>/<page> and wrapped as
    help/index.jsp?topic=/<plugin>/<page> (also %2F and %252F encoded). The
    index.jsp form is an Eclipse frameset and does not hold the topic body.
  - When the archive is overloaded it answers with an HTML "Temporarily Offline"
    page; such responses are treated as retryable errors.

Python 3 standard library only.
