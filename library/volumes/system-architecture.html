2. System overview and block diagram #

Verified summary (MEASURED unless noted):

  • 1 populated processor: Intel Xeon E5606, family 6 model 44 (0x2c) stepping 2, 4 cores, 4 threads, 2.13 GHz, 8 MB L3 (C-CPU, C-OS lscpu). Second socket empty: SMBIOS has two type 4 records, "Node 1 Socket 1" (Populated, Enabled) and "Node 1 Socket 2" (Status: Unpopulated) (C-OS dmidecode type 4). Max two processors DOCUMENTED (S-001 p.7 Table 1 and p.12, S-002 p.7 Table 1).
  • Chipset: Intel 5520 IOH (PCI ID 8086:3406) plus ICH10 (82801JIB LPC 8086:3a18) (C-TVNN). S-001 spec table names "Intel 5520" as chipset (DOCUMENTED); ICH10 is named in no vendor document read so far, only in the capture.
  • IMM (first-generation BMC) with embedded Matrox G200eV video behind a Vitesse VSC452 "SuperBMC" bridge (C-VVV 06:00.0, 07:00.0; S-001 spec table, S-002 Table 1 for the video-in-IMM statement).

Observations:

  • Three memory channels (one device group per channel, MEASURED) match S-001 p.7 Table 1 ("Up to 18 DIMM sockets (9 DIMMs per processor)"), S-001 p.14 Memory options ("Each processor has three memory channels, and there are three DIMMs per channel") and S-002 p.120 Table 11 (channel 0 = DIMM 1, 2, 3, 10, 11, 12; channel 1 = 4-6, 13-15; channel 2 = 7-9, 16-18): 3 channels x 3 connectors per CPU, DOCUMENTED. EDAC reports max_location: channel 2 slot 2 (captures/2026-10-19_mem_storage_memory.txt, MEASURED). Details: X3650M3_MEMORY.md.
  • Two QPI link/physical function pairs exist (links 0 and 1). Which one is wired to the IOH, and whether the other is wired to the CPU 2 socket, is not shown by any capture: UNKNOWN. Link status registers were not read (the captures are plain lspci dumps; see Open questions).
  • i7core_edac binds to ff:03.0 and reports "1 memory controller(s) found" (C-OS dmesg); coretemp and the Intel 5500 hwmon driver are loaded (C-RES hwmon names intel5500, coretemp).
  • S-001 p.12 states QPI is a point-to-point link between processors and between a processor and the I/O hub (DOCUMENTED); the "up to 25.6 GBps" figure is quoted from S-001 and refers to the maximum bidirectional link bandwidth at 6.4 GT/s (S-001 says "high-speed (up to 25.6 GBps)"; derivation not given there).

Notes:

  • Root port numbers 4, 6 and 8 do not exist on this IOH variant in the capture (no devices 00:04, 00:06, 00:08). The 5520 root-port numbering skips these. Reason not documented: UNKNOWN. The DSDT nevertheless defines an object PCI6 with _ADR 0x00060000 (C-HEX, byte-level decode, MEASURED) although no device 00:06.0 is enumerated; there is no DSDT object with _ADR 0x00020000 for the present root port 00:02.0.
  • Lane budget (CANDIDATE): root port widths 2 + 2 + 8 + 8 + 8 + 8 = 36 PCIe lanes, plus x4 ESI. This arithmetic is derived from the measured LnkCap values (C-VVV) only; the lane count of the 5520 itself is not in any vendor document read.
  • Subsystem ID of IOH functions is 1014:xxxx (IBM) for the root ports (e.g. 1014:3408, C-SYSFS) and 1014:7270 for 00:00.0.
  • The ESI link (IOH side) is x4 at 2.5 GT/s with "Surprise+ LLActRep+ BwNot+" capabilities (C-VVV 00:00.0). ESI is Intel's DMI-compatible interface between 5520 and ICH10. The ICH10 end of the link has no PCI configuration function, so link width/speed from the ICH10 side cannot be read: UNKNOWN. The DMI/ESI relationship is CANDIDATE (no vendor document read names it).
  • VT-d: one DMAR DRHD unit at 0xfe710000 (flags 0x1, include-all) with ecap f020fe (C-OS dmesg, C-HEX DMAR). Linux enables interrupt remapping "in xapic mode" and queued invalidation (C-OS dmesg). The RMRR region 0x7d750000-0x7d7cffff is claimed by the USB controllers (1a.0, 1a.1, 1a.7, 1d.0, 1d.1, 1d.2, 1d.7), most likely for IMM virtual media/legacy USB (CANDIDATE). The ATSR lists the six IOH root ports 00:01.0, 02.0, 03.0, 05.0, 07.0, 09.0 (C-HEX DMAR, MEASURED decode).

Riser/slot form factors and riser-to-slot assignment: S-001 p.23 (I/O expansion options) and S-002 PCI adapter guidelines p.54 (slots 1-4 form factors); the dedicated RAID slot: S-001 p.7 Table 1 ("one slot is dedicated to RAID controller"), S-001 p.18 and p.23. All DOCUMENTED.

Consistency checks:

  • S-002 p.7 Table 1 note 2 says ServeRAID controllers sit in an x8-mechanical slot "x4 electrical" and run at x4 bandwidth; the measured ICH10 root port 1 is x4 (2.5 GT/s) (C-VVV 00:1c.0). Consistent (DOCUMENTED + MEASURED).
  • SMBIOS type 9 lists System Slot 1-4 only, all "x8 PCI Express", and marks slot 4 "In Use" and slots 1-3 "Available"; the RAID slot is not listed (C-OS dmidecode). Consistent with the mapping above (MEASURED).
  • SMBIOS slot lengths: Slot 1 Long, 2 Short, 3 Long, 4 Short (C-OS dmidecode); S-001 p.23 gives 1 FH/FL, 2 LP, 3 FH/FL, 4 FH/HL. Consistent.
  • The M1015 link is 2.5 GT/s although the controller supports 5.0 GT/s (C-SYSFS: max 5.0 GT/s x8): the limit is the ICH10 root port (2.5 GT/s x4). CANDIDATE explanation for "downgraded"; matches the root port LnkCap.
  • Onboard Broadcom NICs sit on IOH root port 1 as a two-function device; link is 5 GT/s x2 while the BCM5709 supports x4 ("downgraded", C-SYSFS/C-VVV 0b:00.x). The root port is x2 capable only (LnkCap x2). MEASURED.
  • IOH root port 00:02.0 (bus 10-14) has no S-001/S-002 counterpart and no slots entry. CANDIDATE: it is wired to the optional dual-port Ethernet daughter card connector (S-001 p.24 states the daughter card uses a dedicated board connector and consumes no PCIe slot). Not verified because no daughter card is installed: UNKNOWN.
  • Riser variants (x16 riser = one slot; PCI-X riser) change which slot numbers exist (S-001 p.23, S-002 p.54). The measured server shows the slot numbering of the standard 2x x8 risers for slots 1-4 (all four root ports report x8, SMBIOS type 9 lists four "x8 PCI Express" slots); that both standard risers are physically installed is CANDIDATE (the IOH root-port LnkCap and SMBIOS slot table need not change with the riser). Which riser part numbers are installed is UNKNOWN.

IOMMU grouping (C-VVV, C-STOR, MEASURED): ICH10 root ports 00:1c.0 and 00:1c.4, the M1015 (01:00.0), the Vitesse bridge (06:00.0) and the G200eV (07:00.0) all report "IOMMU group 23". The two ICH10 root ports share one group (CANDIDATE reason: no ACS isolation on the ICH10 root ports; C-VVV shows an Access Control Services capability on the IOH root ports but none on 00:1c.0 or 00:1c.4). Relevant when passing the RAID controller or the video device through to VMs: they cannot be isolated from one another. The SAS2008 HBA at 1f:00.0 is alone in IOMMU group 28 (C-VVV, C-STOR); the onboard NIC functions 0b:00.0/0b:00.1 share group 27 (C-VVV). MEASURED.

3 Kernel driver label for the SAS2008 HBA lspci -k driver "mpt3sas" in C-VVV (from the lspci run) /proc/iomem//proc/interrupts name "mpt2sas" (C-RES, C-PNP) Not a conflict: the kernel module is mpt3sas (which also drives SAS2 controllers) and it names its resources and IRQs for a SAS2008 "mpt2sas" (instance mpt2sas_cm0, X3650M3_STORAGE_RAID.md). One device, one driver; recorded for traceability.
4 Number of USB ports S-001 p.2: five or six USB 2.0 ports (two front, two rear, one internal for an embedded hypervisor, plus one more internal port with the Tape Enablement Kit) S-002 p.7 Table 1: four USB ports plus one or more dedicated internal ports on the SAS riser-card Same hardware described differently; both agree on 2 front + 2 rear.
5 Dedicated RAID slot S-001 p.7 and p.23: RAID uses a dedicated slot Measured: M1015 sits behind an ICH10 PCIe port as "Slot 5", not behind the IOH Not a conflict, but the dedicated slot hangs off the southbridge x4 2.5 GT/s port, which limits the M1015.
6 Remote presence (remote KVM) resolution S-001 p.28: up to 1280 x 1024 at 75 Hz regardless of the system state S-002 p.10 and p.169, S-004 p.504: up to 1600 x 1200 at 75 Hz regardless of the system state Unresolved; same pattern as conflict 1. Not tested (Virtual Media Key presence UNKNOWN).
7 Resolution limit for an optional video adapter (LCD monitor) S-002 p.54: 1600 x 1200 at 75 Hz S-004 p.418: 1600 x 1200 at 60 Hz Unresolved; no adapter installed.
8 Processors in standard models S-001 p.12: "two processors are standard and the server supports two maximum" S-002 p.7 Table 1: "(one installed)"; S-001 p.9 model table lists 1x processor models (e.g. 7945-22x 1x E5606); MEASURED: one CPU in the owner's 7945KEG (C-OS) S-001 p.12 sentence is contradicted by its own model table and by the measurement; maximum of two is uncontested.

15. Open questions / UNKNOWN #

Each item needs a read-only measurement or a document not yet read. No experiments were run for this document.

  1. QPI: speed and width of the CPU-to-IOH link, which of QPI link 0/1 is used, and the state of the second link (CPU 2 socket empty). Needs lspci -xxx / setpci reads of ff:02.x registers or vendor documents. E5606 QPI speed not stated in S-001/S-002; SMBIOS "External Clock: 4800 MHz" is only a CANDIDATE indication. The UEFI exposes a "QPI Link Speed" setting (uEFI.FreqSelect, X3650M3_UEFI.md); its current value was not read.
  2. ESI/DMI: ICH10-side link width/speed and confirmation that ESI is the 5520-ICH10 path (no vendor document read names it).
  3. Purpose of IOH root port 00:02.0 (bus 10-14): daughter card connector (CANDIDATE) or unused.
  4. Which riser cards (part numbers) are installed, and which slot on each riser maps to which IOH port beyond the sysfs slot address (needs a physical inspection or the riser PCB documentation).
  5. Which USB root hub serves the front, rear and internal USB ports; whether a hypervisor key is installed.
  6. Whether the Virtual Media Key is installed, and the IMM's own view of the host interfaces (LAN-over-USB addressing, NC-SI sideband for the shared Ethernet port, serial mux location).
  7. Full DSDT/SSDT AML decode (_PRT mapping of GSIs, sleep states, _OSC, PCI0 device list), full _PSS table, and the P-state/C-state tables.
  8. Clock tree: BCLK value read from a register, PCIe reference clock source, clock generators, spread spectrum, active Linux clocksource.
  9. Whether the missing ACPI tables (SRAT, SLIT, HEST, BERT, EINJ, WDAT) are absent by design or hidden by a firmware setting.
  10. Which UEFI/IMM setting controls ICH10 SATA mode (IDE vs AHCI) and whether AHCI is selectable.
  11. Video: actual maximum resolution supported by the unit (conflict 1); the IMM's PCI function layout seen by the host is only the VGA device (no other IMM PCI function was found in lspci).
  12. Vendor-side confirmation of the "Vitesse VSC452 SuperBMC bridge + Matrox G200eV = IMM" identification (currently CANDIDATE from PCI IDs and subsystem 1014:0369).
  13. Physical interconnect between ICH10 and IMM for IPMB/SMBus (KCS is confirmed; IPMB path is not).
  14. Behavior with a second CPU installed (QPI link 1, additional IOH links, NUMA tables): not testable on the present single-CPU configuration.
