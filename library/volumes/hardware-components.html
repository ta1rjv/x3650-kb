  • FRU 0 "Builtin FRU Device" describes the planar: Board Mfg IBM, Board Product "System Board", Board Part Number 94Y7614, Board Serial [redacted-id], Board Mfg Date 2011-11-28 (printed by ipmitool as 02:00 EET, i.e. 00:00 UTC), Board Extra values 69Y5082, 0002, 0000, 0050, a 16-byte UUID [redacted-id] (equals the SMBIOS system UUID), and a field starting [mac] [mac] (two MAC-like values; the host NICs enp11s0f0/f1 have MACs [mac] and ...:de, so the field carries the onboard NIC MACs). MEASURED (C-IPMI FRU 0; C-OS ip link). 69Y5082 is the system-board FRU number ("System board (P12)", S-005 PDSG 12th ed., sources/text/S-005_46w8286.txt line 9483; later superseded by 81Y6625 / 00AM528; DOCUMENTED), so 94Y7614 is CANDIDATE the planar assembly part number (it occurs in no vendor document). 0002 and 0050 equal the POS ID 0x0002 and VPD ID 0x0050 by which IMM 1.55 etc/vpd_list selects this platform family (destiny/victory, docs/X3650M3_SENSORS_SDR.md 13.3; EXTRACTED match, meaning of the fields CANDIDATE). The meaning of 0000 is UNKNOWN.
  • SMBIOS type 2: Product Name "94Y7614", serial "[redacted-id]", location in chassis "Rear Bottom", features "hosting board, replaceable". MEASURED (C-OS dmidecode type 2).
  • Chassis in FRU 0 reports Chassis Type "Other" and serial [redacted-id] (same as the product serial); SMBIOS type 3 lists chassis serial "none". MEASURED.

4. Jumpers and switches #

Source: S-004 "System-board switches and jumpers", Figures 9-10 and Tables 4-6 (pp. 18-21); IC: c_system_board_switches_jumpers. DOCUMENTED. Any switch or jumper blocks that are not shown in the illustrations are reserved.

Locations (S-004 Fig 9, drawing orientation as in 3.3): J29 (UEFI boot recovery) and J147 (IMM recovery) are near the rear I/O edge, between PCI riser connector 2 and the serial/video connector area; SW4 and SW3 sit side by side (SW4 left of SW3) near the front edge, to the left of the front DIMM bank, next to the fan connector row. DOCUMENTED (figure, approximate).

Safety rules: turn the server off and disconnect all power cords and external cables before moving any switch or jumper; if a clear protective sticker covers the switch blocks, remove and discard it. Default positions of the UEFI and IMM recovery jumpers are pins 1 and 2; with no jumper installed the server behaves as if pins 1-2 were set. Do not change the UEFI recovery jumper after the server is turned on (unpredictable problems).

4.3 Switch block SW4 (default: all Off) #

Switch Function
1 Power-on password override: changing the position bypasses the power-on password check at the next power-on and starts the Setup utility so the password can be changed or deleted. Does not need to be moved back. Does not affect the administrator password.
2 Power-on override: toggle On then Off to force a power-on, which overrides the power-on and power-off buttons (they become nonfunctional). Also used in the OVER SPEC procedures for power channels C and D (S-004 "Power problems").
3 Forced power permission: overrides the IMM power-on checking process (trained service technician only)
4 Reserved

SMBIOS type 12 reports "SW? TPM Physical Presence Switch, J? TPM Physical Presence Jumper" (unnumbered placeholders; the switch is SW3-2 per S-004). MEASURED (C-OS dmidecode type 12) / DOCUMENTED.

Notes for the owner (CANDIDATE, reasoning: derived from the DOCUMENTED function descriptions, not tested):

  • SW3-1 (clear CMOS) is the documented way to reset UEFI settings, for example after the depleted CMOS battery (section 12) loses configuration; this requires AC removal and cover removal.
  • J29 pins 2-3 is the fallback if a UEFI update corrupts the primary ROM page; J147 pins 2-3 for a bad IMM update. Because this server is the Proxmox host and the agent's own host, use only with explicit owner approval.
  • J29 is close to PCI riser connector 2; the documented in-band manual recovery procedure says to "remove any adapters that impede access to the UEFI boot recovery jumper block (J29)" (S-004 pp.372-373, steps 5 and 15). DOCUMENTED. On the owner's server the slot 4 HBA sits on riser 2 and may have to be removed (CANDIDATE, reason: riser 2 is next to J29 in Fig 9; not verified physically).

5.3 Power channel error LEDs (12 V channels) #

A 12 V channel error LED indicates an overcurrent condition. IC:t_solving_power_problems "Table 1" and IC:r_power_problems (S-004 "Power problems"). DOCUMENTED.

LED Components on the channel (troubleshooting order)
A CD/DVD (optical) drive, fans, hard disk drives, hard disk drive backplanes
B PCI riser-card assembly in PCI connector 1, DIMMs 1 through 16, microprocessor 2
C Tape drive if installed, SAS riser-card assembly, DIMMs 1 through 8, microprocessor 1
D Microprocessor 1, system board
E Optional PCI video graphics adapter power cable (J154) and adapter, PCI riser-card assembly in PCI connector 2, microprocessor 2
AUX All PCI adapters and PCI riser-card assemblies, SAS riser-card assembly, operator information panel assembly, optional two-port Ethernet card

The DIMM ranges are inconsistent inside the source (channel C: "DIMMs 1 through 8" in the table, "DIMMs 1 through 9" in the OVER SPEC procedure; channel B lists 1-16 although there are 18 sockets). Recorded as conflict C-2.

OVER SPEC LED on the light path panel plus one of these LEDs means a power-supply overload on that channel (section 6.3). For channel C and D the procedure moves SW4 switch 2 to On (force power on) so the board can be tested.

15. Removal and replacement notes for the owner #

All DOCUMENTED (S-002 Chapter 2; S-004 Chapter 5; IC:c_removing_replacing_consumble_parts_tier1_crus, c_removing_replacing_tier2, topic pages t_*). General: read the safety and installation guidelines, handle static-sensitive devices carefully, slide the server out of the rack for cover work. This server is the Proxmox host (docs/AGENT.md): any power-off, reset or component removal that needs power-down stops the lab and the agent; plan maintenance with the owner.

Power supply yes Do not mix types; reconnect and route the cord through the handle; check that the error LED is off and AC/DC LEDs are lit; IMM sees the supply in the bay named Power Supply n (bay mapping UNKNOWN, section 10.3)
