Scope: power supplies (types, part numbers, efficiency, redundancy rules, installed state), a power budget for the installed configuration, power metering and capping (Active Energy Manager, IPMI, DCMI, ACPI P-states), fans and fan control, thermal thresholds and environmental limits, acoustics, and the thermal effect of the UEFI operating modes. Owner's server only.

Truth levels (docs/AGENT.md): DOCUMENTED (vendor document), EXTRACTED (firmware binary), MEASURED (captured from the owner's server), CANDIDATE (inference, reason given), UNKNOWN. Source IDs refer to sources/SOURCES.md. Offline compilation: no command was run against [lab-ip], [lab-ip] or the internet for this document; all MEASURED values come from the captures listed in section 1. Values decoded here from a captured ACPI table dump are MEASURED (the dump was taken from the owner's server); they are firmware-declared values, not electrical measurements, and are marked as such.

Related documents (not repeated here): PSU LEDs, PSU part tables, fan hardware, fan connector LEDs and the measured FRU state in docs/X3650M3_HARDWARE_COMPONENTS.md sections 10, 11, 13.4 and 14; IMM event IDs for fan, temperature and power sensors in docs/X3650M3_ERROR_CODES.md sections 4.2 to 4.6 and 9.3 to 9.4; Setup forms and ASU settings in docs/X3650M3_UEFI.md sections 5 to 7 and Appendix A.

3.4 Redundancy and over-load rules #

  • Up to two supplies; with two supplies and one failing, the other carries the load if the maximum load is below the rating of one supply; above that, "Active Energy Manager can act to minimize the load somewhat so that the server can function with the remaining power supply" (S-002 p.12, DOCUMENTED).
  • No mixing of 460 W and 675 W, HE and non-HE, or AC and DC supplies (S-002 Table 1 note; mixing lights PS and CNFG LEDs, docs/X3650M3_HARDWARE_COMPONENTS.md section 10.1). DOCUMENTED.
  • 460 W behaviour (S-002 printed pp.123-124, Table 14): below 400 W normal; 400 to 460 W with one operational supply "Normal, status warning"; above 460 W "System shutdown" with one supply (or two with one failed); "The server automatically shuts down if the total power consumption exceeds the total power supply output capacity". "You can enable the power capping feature in the Setup utility to control and monitor power consumption". DOCUMENTED.
  • 675 W supplies: no equivalent threshold table in any repository document (UNKNOWN).
  • "Power supply 1 is the default/primary power supply. If power supply 1 fails, you must replace the power supply immediately." (S-002 p.124, DOCUMENTED).
  • IMM redundancy events: "Redundancy Lost ... (Power Unit)" 800b0108-1381xxxx and "restored" 800b0008-1381xxxx (S-004 printed pp.77-78; docs/X3650M3_ERROR_CODES.md section 4.4). DOCUMENTED.
  • Cooling rule: "If the server has redundant power, each of the power-supply bays has a power supply installed in it" (IC:c_system_reliability_guidelines). The rule text does not state what goes into the empty bay of a non-redundant server; the parts list carries a bay filler 49Y4821 for this model family (CANDIDATE: the filler is expected in the empty bay for airflow).

3.5 Installed supply (MEASURED and CANDIDATE) #

  • FRU ID 1 "Power Supply 1": "Device not present"; FRU ID 2 "Power Supply 2": present, all fields generic ("IBM Designed Device", no part number, no serial). Sensor "Power Supply 1" = na, "Power Supply 2" = 0x1. MEASURED (C-IPMI).
  • All PS 1 and PS 2 discrete fault sensors (Fan, Therm, OP, VCO, 12V OV/UV/OC) read 0x1 with status 0x0180, the same value as healthy presence sensors; chassis status reports no power fault and the SEL holds no PSU event. CANDIDATE: 0x1 is the non-fault state (bit meaning to be decoded in docs/X3650M3_SENSORS_SDR.md). "Power Unit" = 0x0. MEASURED.
  • Wattage, type (460 W / 675 W / 675 W HE) and part number of the installed supply: the IPMI FRU carries no part number, but the IMM VPD reports FRU 39Y7229 and part 39Y7228 (MEASURED 2026-10-21, captures/2026-10-21_imm_wsman_read_inventory.txt GetVitalProductData; captures/2026-10-21_imm_cim_read_inventory.txt CIM_PhysicalPackage). 39Y7229 is a 460 W AC CRU in the parts table (docs/X3650M3_HARDWARE_COMPONENTS.md 13.4). CANDIDATE strong: 460 W AC; reasons: this FRU match and the earlier model-22x inference (S-001 Table 16). Label not inspected.
  • Which physical bay is used and whether a filler sits in the other bay: UNKNOWN (conflict C-5 in the hardware document: IPMI FRU/SDR name the supply "Power Supply 2", the IMM VPD names it "Power Supply 1", S-002 says the standard supply goes into bay 1).
  • Consequence: no power redundancy. MEASURED (one supply present).

4.3 Budget result (CANDIDATE) #

A pure bottom-up sum is not possible because the platform base load (board, IMM, fans, NICs, VR losses) and the DIMM power are UNKNOWN. The budget therefore starts from the MEASURED 80 W and adds a worst-case increase per component on top of it. Each increase assumes the component drew nothing at capture time, which double counts the idle share and makes the result an upper bound.

Term Increase (W) Reason
Measured base (all components, capture-time load) 80.00 C-IPMI "Avg Power"
CPU from capture-time state to full TDP +80.00 80 W TDP, assumes the CPU drew 0 W at capture time (over-estimate)
M1015 idle to disk stress +3.36 12 V x (1.81 - 1.53) A, S-032 Table 3.6
SAS HBA idle to stress +3.36 same as M1015 (CANDIDATE, same chip)
Two HDDs fully active +20.00 2 x 10 W (S-001 generic upper value; the Hitachi is spun down today)
DIMM at full load +10.00 placeholder allowance, no source (CANDIDATE, UNKNOWN real value)
Fans ramping up +30.00 placeholder allowance, no source (CANDIDATE, UNKNOWN real value)
Upper bound 226.72 (about 227 W) sum

Arithmetic: 80.00 + 80.00 + 3.36 + 3.36 + 20.00 + 10.00 + 30.00 = 226.72 W.

Interpretation (CANDIDATE):

  • Against a 460 W supply: about 227 W is below the 400 W "status warning" point of S-002 Table 14 by about 173 W (400 - 226.72 = 173.28) and uses about 49 percent of the rating (226.72 / 460). Against a 675 W supply: about 34 percent (226.72 / 675). Either way one supply carries the installed configuration with margin, and power capping is not needed for over-load protection.
  • The two placeholder allowances (40 W total) carry the largest uncertainty; even if both were doubled the bound (266.72 W) stays below 400 W.
  • If the "Avg Power" sensor reports DC output (UNKNOWN, section 5.2), the AC input at the upper bound would be about 226.72 / 0.9076 to 226.72 / 0.9291 = 249.8 to 244.0 W for a 675 W-class supply (efficiency between the 20 and 50 percent points of section 3.3, the bound being at about 34 percent load). No 460 W efficiency data exists.
  • Energy at the measured level, if 80 W were constant: 80 W x 8760 h = 700.8 kWh per year. A single sample is not a valid average; a time series is listed in section 12.
  • The measured 80 W is below both documented idle/minimum references (120 W idle, 194 W or 90 W minimum configuration); see D-2 in section 11.

Capping on this server is therefore only reachable through the AEM application (IBM Systems Director) talking to the IMM. The protocol AEM uses (IPMI OEM commands or CIM) is not documented in the repository (UNKNOWN). IBM Systems Director / AEM availability for the owner: UNKNOWN.

5.2 Measured metering #

  • IPMI sensor "Avg Power" 80 W (ID 2Eh, entity 21.0, no thresholds). MEASURED (C-IPMI). Averaging window, AC or DC basis, and accuracy are UNKNOWN. CANDIDATE: AC input, reason: the IMM feature list says "Query power-supply input power"; not proven for this sensor. FW-IMM 1.14 (YUOO73M): "Improved the accuracy of power readings on 3550 M3, 3650 M3, and 3620 M3" (DOCUMENTED; the installed 1.30 includes it).

DCMI power reading and DCMI power limit are therefore not available. Note: generic ipmitool sensor reads of "Avg Power" work and are the in-band metering path.
  • The current state of uEFI.EnergyManager on the owner's server is UNKNOWN (no ASU capture); POST code 3828004 is not present in the captured SEL, which only holds IPMI-format entries (the UEFI POST event log was not captured).

5.3 OS-visible power controls (MEASURED, with firmware context) #

  • ACPI SSDT3 (OEM table ID "PSTATEPM") defines _PSS (8 P-states, section 4.1), _PCT, _PPC, _PSD for each of the 4 logical CPUs. No _CST, _TSS or _PTC object exists in DSDT or SSDT1-3; FADT CST_CNT = 0, PSTATE_CNT = 0, DUTY_OFFSET = 0, DUTY_WIDTH = 0, P_LVL2_LAT = 101, P_LVL3_LAT = 1001, preferred PM profile 4.   • CANDIDATE interpretation (ACPI specification semantics, the specification is not mirrored in the repository): P_LVL2_LAT > 100 and P_LVL3_LAT > 1000 mean the firmware advertises no ACPI C2/C3 through the FADT; DUTY_WIDTH = 0 and no _TSS mean no OS-controlled T-state throttling.   • One core ran at 1693.709 MHz while the others ran at about 2133 MHz (C-CPU), and lscpu reports min 1197 MHz: OS frequency scaling is active, so "Processor Performance States" is enabled in UEFI (CANDIDATE, strong, reason: P-state transitions are visible to the OS). The cpufreq driver and governor are UNKNOWN (cpupower not installed, C-OS).
  • intel_powerclamp is loaded (MEASURED); it is an OS-side idle-injection mechanism, unrelated to AEM (CANDIDATE).

6. Fans and fan control #

6.1 Hardware (summary) #

Three hot-swap dual-rotor 60 mm fan modules (CRU 49Y5361) in a fan cage (49Y5362); "3 counter-rotating hot swap fans with N+1 redundancy" and "IBM Calibrated Vectored Cooling" (S-001 p.7); all three must be installed; a removed fan must be replaced within 30 seconds, a failed fan within 48 hours (IC:c_system_reliability_guidelines). Fan numbering, connector LEDs and part numbers: docs/X3650M3_HARDWARE_COMPONENTS.md section 11. DOCUMENTED.

PSU fans are separate; each supply has an IMM "PS n Fan Fault" sensor (C-IPMI, MEASURED; event 80070204-0a0nxxxx, S-004 p.73).

9.2 Expected thermal and power effect on this server (CANDIDATE unless noted) #

  • Turbo Mode has no effect: the E5606 has no Turbo Boost (S-001 p.12, DOCUMENTED; no "ida" flag, MEASURED).
  • Processor Performance States: with P-states the CPU can drop from 2128 MHz (80.0 W declared) to 1197 MHz (46.3 W declared); the declared difference is 80.000 - 46.255 = 33.745 W at full load (C-ACPI arithmetic). At light load most savings come from idle states rather than P-states, and their effect is UNKNOWN without cpuidle statistics. Performance mode disables P-states and C1E, so the CPU stays at 2128 MHz and idles at a higher power; the IMM has a "fan control enhancement for performance mode" (IMM 1.14, DOCUMENTED), so higher fan speed is expected in Performance mode (CANDIDATE, mechanism UNKNOWN).
  • Memory and QPI "Minimal Power" lower memory and link clocks; with one DIMM the absolute saving is small (CANDIDATE; no wattage source). The DIMM already runs at 1067 MT/s (docs/X3650M3_MEMORY.md).
  • Acoustic mode is described as lowest power and lower acoustic level (EXTRACTED help text); how the IMM fan curve changes in that mode is not documented (UNKNOWN).
  • C-states: UEFI 1.22 defaults "CPU C State" (uEFI.ProcessorCcxEnable) to Disable and the package C-state limit to ACPI C2 (1.14: C3); the FADT of the installed firmware advertises no ACPI C2/C3 (section 5.3). Deeper C-states would lower idle power and heat but the effect on this server is UNKNOWN until measured.
  • PCI Express ASPM (uEFI.PcieAspm*, Disable default, "Enable L1 Only") lowers idle link power of PCIe devices; affected devices here are the two SAS2008 adapters and the BCM5709 (CANDIDATE, effect UNKNOWN).
  • On-board LAN power (uEFI.ZoarPower, docs/X3650M3_UEFI.md A.1) is a MiscConfiguration setting; its effect on the measured power is UNKNOWN.

Any change of these settings is a UEFI setting change on the Proxmox host that runs the agent: it needs explicit owner approval and a reboot (docs/AGENT.md, A-007). No change is recommended by this document.

9.3 Memory Thermal Mode (EXTRACTED) #

  • Memory form question "Thermal Mode" (qid 0x0013, varstore offset 0x0665): options "Normal" = 0 (default) and "Performance" = 1; help: "Select this to set your Thermal Mode Options. Changes won't take effect until the next boot." (UEFI-HII, 1.22).
  • The 1.14 and 1.22 setup XML contain a Thermal_Mode setting (Normal = 0 default, Performance = 1, Acoustic = 2) with per-mode protected sub-settings: Hysteresis (0 / 1.5 default / 3 / 6 deg C), Upper Boundary Alarm Trip Temperature (default 75 deg C, 0-128), Critical Alarm Trip Temperature (default 80 deg C), memory controller throttle duty cycle (LSB default 3FFF), memory refresh rate (Single default / Double). The whole block is inside an XML comment, so ASU most likely does not expose it (CANDIDATE, reason: commented out in the XML ASU reads).
  • CANDIDATE interpretation: these are DIMM thermal-sensor trip points used by the memory controller for closed-loop memory throttling; the 75/80 deg C values are DIMM temperatures, not ambient. Not verified.
  • UEFI 1.08 fixed "the value of Thermal Mode can not be changed" (FW-UEFI, DOCUMENTED; the installed 1.13 includes it).
