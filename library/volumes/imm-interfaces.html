3. Web interface (HTTP/HTTPS) #

3.1 Transport and login #

  • DOCUMENTED: the web interface is reached by typing the IMM IP address or host name; after login a Welcome page asks for an inactivity timeout (fixed when the global login settings say so), then opens System Status (S-020 p22, printed 14). All login attempts are written to the event log (S-020 p22).
  • DOCUMENTED: HTTP default port 80, HTTPS default 443, both changeable to 1-65535 on the Port Assignments page (S-020 p43). If the HTTP port changes, the URL needs http://host:port/ (S-020 p43).
  • DOCUMENTED: the secure web server needs a certificate (self-signed or CA-signed) before SSL can be enabled; enabling or disabling the HTTPS server takes effect only after an IMM restart (S-020 p84-87, p90). The client must use SSL3 or TLS (S-020 p87). Cryptography mode Basic Compatible (default) or High Security (disables SSL, TLS key at least 128 bits) applies to the HTTPS server and to Systems Director over HTTPS (S-020 p91-92).
  • DOCUMENTED (IMM1 default): IMM.SSL_Server_Enable default value Disabled on IMM1 (Enabled on IMM2), and the HTTPS server certificate default "Private Key and Cert/CSR not available" on IMM1 (S-027 Appendix I, IMM1 column). This gives a documented reason why an IMM1 that was never configured has no working TLS on 443.

3.3 Implementation on firmware 1.30 (captured web UI) #

Summary only; the full analysis, the endpoint table and the 133-operation WS-Man catalogue are in X3650M3_IMM_WEB_API.md and are not repeated here. Sources: the static UI files and WSDLs under sources/imm_web/1.30/ (UI = file under that directory, cited as file:line; retrieval method, SHA256SUMS and CRAWL_LOG.tsv in its README) and the captures named in section 1.

  • EXTRACTED (code base): 106 of the 129 files carry the header "(C)Copyright 2007-2008, American Megatrends Inc." (grep over sources/imm_web/1.30; for example index.html:1-24). CANDIDATE: the UI derives from the AMI MegaRAC BMC web stack, customised by IBM ("iBMC" names, IBM resource URIs). Reason: AMI copyright and authors plus AMI gateway code in lib/xmit.js; the word "MegaRAC" occurs in no stored file and no vendor document in the repository states the lineage (WEB_API 2.1).
  • EXTRACTED (UI architecture): / (index.html) is a JavaScript frameset with frameHeader, frameTree and frameMain (index.html:82-88). Content pages are page/*.html with logic in impl/<page>_imp.js. The top window loads the WS-Man library (lib/wsman/wsman.js, index.html:39-51), downloads six WSDLs after login and turns every WSDL operation into a global function top.<Operation>(input, callback) (home_imp.js:161-231). Almost every page reads and writes IMM state through these calls (WEB_API 3).
  • EXTRACTED (WS-Man client): POST <scheme>://<host>/wsman (home_imp.js:51), Content-Type: text/xml, no SOAPAction header (lib/wsman/soap.js:64-66, lib/wsman/WSDLOperation.js:150-154). The WSDLs are fetched by WS-Transfer Get with ResourceURI wsman:system/catalog/2005/06/WSDL1.1 for the six IBM resource URIs http://www.ibm.com/iBMC/sp/{Monitors, Tasks, iBMCControl, iBMCNWProtocol, ServiceAdvisor, Scalability} (sources/imm_web/1.30/README.md). MEASURED: every WSDL GetResponse names http://[lab-ip]/wsman as wsa:From, i.e. WS-Man is served by the web server on port 80 (wsdl/*.wsdl.xml headers). Together the six WSDLs declare 133 operations (Monitors 17, Tasks 20, iBMCControl 54, iBMCNWProtocol 13, ServiceAdvisor 21, Scalability 8; README.md); the stored UI calls 92 of the names (WSMAN_OPERATIONS.tsv). Operation list: WEB_API 6; mapping to S-020 pages, CLI, ASU and CIM profiles: WEB_API 7.
  • EXTRACTED (main endpoints besides /wsman): /session/create, /session/activate, /session/deactivate, /session/expiry/{increase,resume} (session); /br/backup, /br/restore (configuration backup/restore); /spevents.elg (event log download); /certs/*.der, /ipsec.certs/*.der (certificates and CSRs); multipart uploads to page/tasks_updatefirmware_verify.html (firmware image); /kvm/kvm/{jnlp,activx,activx64} (remote control launcher). Paths, purposes and file:line sources: WEB_API 4.3. No client URL contains "cgi"; CANDIDATE: the handlers are lighttpd plugins (reason in WEB_API 2).
  • EXTRACTED (authentication and session, client side): login is POST /session/create with the raw body <user>,<password>, comma-joined and unencoded (home_imp.js:348-353); the reply starts with ok, unauthorized, locked or existing (home_imp.js:356-402). After GetPasswordStatus and UserLogOniBMC the session page sets the inactivity timeout and sends POST /session/activate with session_expiry=<seconds> (home_imp.js:451-499). The session id travels as a session_id cookie or, without a cookie, as an HTTP header session_id (lib/wsman/network.js:31-34, 142-145), in the URL fragment and as a ?session_id= query parameter on download and KVM URLs. WS-Man HTTP 403/404 is treated as an expired session (home_imp.js:143-147). This complements the DOCUMENTED login behaviour in section 3.1 (S-020 p22). Server-side enforcement and server-set cookie attributes are UNKNOWN (client code only; no Set-Cookie captured). Full sequence: WEB_API 4; security observations: WEB_API 8.

4. Legacy CLI (SSH and Telnet) #

4.1 Access and limits #

  • DOCUMENTED (S-020 p133-135): reached through Telnet or SSH to the IMM IP address; IMM authentication first; prompt system>; session ends with exit. Syntax command [arguments] [-options], case sensitive, one command per line, 160-character line limit, no continuation, Backspace is the only editing key, Up/Down and history give the last eight commands (!n re-runs one). Command output is limited to 2048 characters and is shown only after the command finishes (not in serial redirect mode). Every command accepts -h, -help and ?.
  • DOCUMENTED: multiple concurrent CLI sessions are allowed across Telnet and SSH; at most two Telnet sessions; the Telnet session count is 0, 1 or 2 and 0 disables Telnet (S-020 p134, p42, p52).
  • MEASURED (cli_baseline, over SSH): banner lines "Legacy CLI Authorization" and "Legacy CLI Application", prompt system>; help lists 34 commands (section 4.2). SSH client requirements (legacy algorithms, -tt) are in docs/X3650M3_IMM_ARCHITECTURE.md section 5.2 and assumption A-004.

6. Serial over LAN and serial redirection #

6.1 Two serial paths #

  • DOCUMENTED (S-020 p41): the IMM provides two serial ports for redirection.   • DOCUMENTED (S-020 p42-43): console 1 in the CLI starts redirection; all COM2 traffic goes to the Telnet/SSH session; the exit key sequence returns to the CLI ("ESC Q" example, press Esc then q). Up to two Telnet sessions can view a redirected port concurrently.

9. SLP (427) #

  • DOCUMENTED: port 427 is reserved for SLP and cannot be reassigned (S-020 p44 Table 3); SLP is one of the protocols on the Network Protocols page (S-020 p27, p49), but S-020 has no SLP configuration section. The CLI configuration command list includes slp without a section (S-020 p139).
  • MEASURED: slp is in the 1.30 help as "View/edit SLP parameters" (cli_baseline). 427/tcp open (nmap "svrloc?", unconfirmed), 427/udp open "Service Location Protocol 2" (nmap_udp). The display shows one parameter, -t multicast (cli_settings line 80); its meaning is not documented (CANDIDATE: SLP address type multicast vs broadcast, reason: value name only).
  • DOCUMENTED (S-025 section 7, Updates): the update utility discovers the IMM by SLP multicast on the LAN over USB interface when the default address fails. EXTRACTED (architecture doc section 9.3): iflash64 contains SLP attribute and service request strings.
  • DOCUMENTED (changelog 1.55): "Fixed the OpenSLP heap-related memory corruption which was found in H4B." So the SLP daemon is OpenSLP and 1.30 predates the fix (CVE number from docs/X3650M3_FIRMWARE_HISTORY.md, not from the changelog).
  • UNKNOWN: advertised service types and attributes, scope, whether SLP answers on the external LAN and on LAN over USB equally, multicast vs unicast behavior. ASU IMM.SLPPortControl exists only in S-027 (IMM2 port control list); no IMM1 way to close 427 is documented for 1.30.

10. LAN over USB (in-band network interface) #

Internals, USB descriptors, documented and conflicting addresses and the update protocol are in docs/X3650M3_IMM_ARCHITECTURE.md sections 4.2 and 9.3 and conflict 1. Interface-level facts only:

  • DOCUMENTED: the IMM presents an internal Ethernet NIC to the OS; IMM side static 169.254.95.118/255.255.0.0 (S-020 p129). Called "USB in-band interface" or "commands on USB interface" in the web UI (S-020 p31-32, p129).
  • DOCUMENTED (S-020 p32): "To prevent any application that is running on the server from requesting the IMM to perform tasks, you must disable the USB in-band interface." Disabling stops in-band flash utilities and ASU over this path (ASU still works with an IPMI driver), does not affect remote presence USB devices; disable the watchdog timeouts too.
  • DOCUMENTED control points: web System Settings > Miscellaneous "Allow commands on the USB interface" (S-020 p32); CLI usbeth -en enabled|disabled (S-020 p150); ASU IMM.LanOverUsb, which must be set with --kcs because the link disappears during the set (S-026 printed p17; S-026 Lenovo edition section on LAN over USB); UEFI "Commands on USB Interface Preference" (S-022 p8).
  • DOCUMENTED: ASU uses LAN over USB by default and falls back to KCS; ASU enables a disabled LAN over USB link for its own use and disables it again afterwards (S-026 printed p16). The asu immcfg sub-application configures the host side (--autocfgdhcp, --autocfgstatic with host 169.254.95.120 and IMM 169.254.95.118; S-026 printed p30-31).
  • CANDIDATE: the IMM network services (web, CLI, CIM, SLP) are reachable from the host over this link once the host interface has an address. Reason: S-020 p32 wording ("any application ... requesting the IMM to perform tasks") and S-025 section 7 (FTP and SLP over this link); no capture exists because the host interface is DOWN.
  • MEASURED: host device 04b3:4010 present, driver cdc_ether, interface enx5ef3fce08adf DOWN with no address (lanoverusb_host). IMM side: usbeth -en enabled (MEASURED, cli_settings line 26), so only the host side is unconfigured. Server timeouts (OS watchdog, loader watchdog, -f) are all disabled (cli_settings lines 20-23), which is the documented safe combination if the USB in-band interface is later disabled (S-020 p32).

11. ASU as a configuration interface #

  • DOCUMENTED (S-025 BMC configuration section, "New Method"): all IMM settings are stored on the IMM file system and are directly accessible by ASU; most web settings are also ASU settings; ASU works locally and remotely.
  • DOCUMENTED (S-026 printed p16-17): connectivity options: no option = LAN over USB with default settings, then KCS; --kcs = KCS only, no authentication; --host <IMM IP> with credentials = remote over the IMM LAN. ASU 3.0.0 or later is required for the IMM (S-020 p126).
  • UNKNOWN: the wire protocol ASU uses for a remote (--host) connection to an IMM1. The CIM-first, then IPMI LAN, then KCS order in S-026 printed p35 is written for IMM2-based systems (FoD) and is not imported.
  • Interface-relevant IMM1 setting names (S-026 printed p22-24, ESXi list for IMM-based servers): IMM.HTTPPort, IMM.SSLPort, IMM.TelnetPort, IMM.SSHPort, IMM.SNMP_AgentPort, IMM.SNMP_TrapPort, IMM.CIMOverHTTPPort, IMM.CIMOverHTTPSPort, IMM.SNMPTraps, IMM.Community_Name.1, IMM.SSL_Server_Enable, IMM.CIMXMLOverHTTPS_Enable, IMM.SSL_Client_Enable, IMM.SSH_Enable, IMM.SerialRedirectionCLIMode1, IMM.SerialBaudRate, IMM.WebTimeout, IMM.LockoutPeriod, IMM.User_Authentication_Method, IMM.AccountSecurity and the per-user IMM.SNMPv3_*.1 set.
