For every tool: purpose, local copies (path + SHA256), operating-system support and whether it can run on this Proxmox VE host, transport to the server, read-only versus state-changing commands, and documented caveats.

Rules: docs/AGENT.md. Truth levels: DOCUMENTED (vendor document), EXTRACTED (from a file in the repository, static inspection only), MEASURED (captured from the owner's server), CANDIDATE (inference, reason given), UNKNOWN. Nothing in this document was executed against the server while writing it; all EXTRACTED facts come from offline static inspection (file, readelf, sha256sum, archive listings) in a scratch directory; no vendor binary was executed (section 15).

Command labels used in every example:

  • read-only - reads state only (it may still write local output files or start a vendor program as root).
  • STATE-CHANGING - changes firmware, settings, logs, power, network or users; needs explicit owner approval (docs/AGENT.md). This server IS the Proxmox host [lab-ip] that runs the lab and the agent; an IMM reset, server reboot, power action or failed flash takes everything down.
  • Placeholders: <IMM_USER>, <IMM_PASSWORD_FILE>, <IMM_IP> (the owner's IMM is [lab-ip]). Credentials are never stored in this repository; prefer password files or environment variables over command-line passwords.

3. Transports: KCS, LAN over USB, IMM external LAN, bootable media #

Details of the interfaces themselves are in docs/X3650M3_IMM_ARCHITECTURE.md sections 4.1 (KCS), 4.2 (LAN over USB), 5 (network services) and 9.3 (in-band update protocol). Tool-relevant points:

  • KCS (in-band IPMI system interface): used by ipmitool (OpenIPMI /dev/ipmi0), by ASU as fallback or with --kcs, by iflash with --kcs. DOCUMENTED (S-026 v10.6 PDF p19): "The local connection over the KCS interface does not require authentication". Any root process on the host therefore has unauthenticated IMM access.
  • LAN over USB (in-band virtual Ethernet to the IMM, IMM at 169.254.95.118): used by ASU (default), DSA, UXSPI, BoMC media and the iflash packages. DOCUMENTED: ASU "attempts to connect and automatically configure the LAN over USB interface if it detects that this interface is not configured" and disables it again afterwards if it was disabled before (S-026 PDF p19-20); DSA Portable and UXSPI both warn that running them changes the route table of the 169.254.95.x network and can crash cluster software (DSA 10.1 readme section 9.0; UXSPI 10.2 readme "Duplicate IP addresses when updating IMM, uEFI, and DSA"). DOCUMENTED (ASU 10.3 readme section 2.2): "there must be no network device on the system configured with an IP adress of 169.254.x.y other than the CDC Ethernet Device".
  • The helper script that performs this host-side configuration is cdc_interface.sh (EXTRACTED: version 1.0.7 in the ASU 10.3 tgz, SHA256 8e7fe3809b102f878e68c6de1faba3477bdc2fd01dc5831ae2e9d5ac9b213457; version 1.0.5 in the UEFI 1.14 package, SHA256 5fc16ee9f1298f4c71c2060c9e01a0f9d997ff1ed0bf636931f83ad2463718e6). Its OS detection reads /etc/redhat-release, /etc/SuSE-release and /etc/vmware-release, and it may edit /etc/modprobe.conf or /etc/modules.conf (keeping /etc/ORIGINAL. copies) and use ifconfig/ifup/ifdown and /etc/sysconfig/network (EXTRACTED, grep of the script). No Debian branch was found; its behavior on this Proxmox host (ifupdown2, Linux bridges for the VMs) is UNKNOWN. CANDIDATE risk: changes to host networking on the lab hypervisor; treat any tool run that touches LAN over USB as STATE-CHANGING for the host.
  • IMM external LAN (out-of-band): ASU --host/--user/--password(-file), ipmitool -I lanplus, IMM web/SSH CLI. Works with the host OS down (S-026 PDF p20). The TCP port ASU uses for out-of-band IMMv1 access is not stated in the local sources (UNKNOWN; CIM on 5988/5989 is CANDIDATE, reason: S-026 limitation 9 and immapp mention CIM HTTP/HTTPS, not verified for IMMv1).
  • Bootable media (BoMC, Preboot DSA ISO, embedded Preboot DSA via F2): the tools run on the server instead of Proxmox; using them requires a reboot of the lab host (STATE-CHANGING).

4. ASU - Advanced Settings Utility #

4.1 Purpose (DOCUMENTED) #

ASU modifies firmware settings from the command line: UEFI settings, IMM settings, VPD, iSCSI boot settings, and on IMM-based servers remotely over the IMM external LAN. "The ASU does not update any of the firmware code" (S-026 v10.6 PDF p7-8). It also generates/imports/exports IMM certificates and offers immapp (host power, SEL and IMM log functions, ASU 9.40+, S-026 PDF p49). The UEFI setting names of this server (209 top-level settings in UEFI 1.22, uEFI.<mriName>) are in docs/X3650M3_UEFI.md section 7 and Appendix A; they are not repeated here.

4.3 Operating system and runtime #

  • DOCUMENTED supported OS (S-026 v10.6 PDF p9, 32- and 64-bit): Windows 2008 to 2016, WinPE 1.6/2.0/2.1, RHEL 6/7, SLES 10/11/12, VMware ESX/ESXi 4.0 to 6.0. Debian/Proxmox is not listed.
  • DOCUMENTED (same page): distributions without the compatibility libstdc++ may fail with "libstdc++-libc6.1-1.so.2: cannot open shared object file". EXTRACTED: asu64 10.3 is "ELF 64-bit LSB executable, x86-64, dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, for GNU/Linux 2.4.0, with debug_info, not stripped"; its NEEDED libraries are librt.so.1, libdl.so.2, libcrypt.so.1, libm.so.6, libpthread.so.0 and libc.so.6 (no libstdc++), highest versioned glibc symbol GLIBC_2.3.2. CANDIDATE: it can start on a current x86-64 Debian (reason: only base glibc libraries, old symbol versions); libcrypt.so.1 presence on the host was not checked. Not tried.
  • Linux IPMI driver: OSA/MSI driver with mapping layer, or the distribution OpenIPMI driver (S-026 PDF p13). The host has the in-kernel ipmi_si/ipmi_devintf (MEASURED, section 2).
  • ASU 10.3 readme section 1.5: "Definition files must be at version 2.4.1 or below." Section 2.2: ASU loads the CDC Ethernet driver through cdc_interface.sh, which must be in the same directory as asu.

4.4 Transport (DOCUMENTED, S-026 v10.6 PDF p19-21, p67-70) #

  • No connection options: ASU tries LAN over USB with the IMM default account, then falls back to KCS (needs the IPMI driver).
  • --kcs: KCS only, no authentication.
  • --host <IMM_IP> --user <IMM_USER> --password ... (or --password-file <file>): out-of-band over the IMM external LAN; all three required; since ASU 9.41 there is no default user/password out-of-band. The OS may be off.
  • --noimmlancfg: skip the automatic LAN over USB configuration when the interface was configured manually.
  • --mtsn / --net: locate an IMM on the LAN by machine type, model and serial.
  • The IMM LAN-over-USB IP settings IMM.LanOverUsbIMMIP, IMM.LanOverUsbIMMNetmask, IMM.LanOverUsbHostIP are for IMM2 build 1AOO45F or later: "IMMV1 is not supported" (S-026 PDF p21).
  • S-020 (IMM v1 user's guide) PDF p125: ASU 3.0.0 or later is required to manage the IMM; if LAN over USB is disabled, ASU needs IPMI device drivers.

4.5 Commands #

Read-only (they read settings; save writes a local file only):

./asu64 version                                        # read-only
./asu64 show all --kcs                                  # read-only (all settings via KCS, no LAN-over-USB setup)
./asu64 show uEFI --kcs                                 # read-only
./asu64 show uEFI.OperatingMode --kcs                   # read-only (setting from docs/X3650M3_UEFI.md)
./asu64 showvalues uEFI.OperatingMode --kcs             # read-only (allowed values)
./asu64 showdefault uEFI --kcs                          # read-only
./asu64 showgroups --kcs                                # read-only
./asu64 comparedefault uEFI --kcs                       # read-only
./asu64 save <local_file> --kcs                         # read-only on the server; writes <local_file>
./asu64 nodes --kcs                                     # read-only
./asu64 immapp powerstate --kcs                         # read-only
./asu64 immapp showsel --kcs                            # read-only
./asu64 immapp showimmlog --kcs                         # read-only
./asu64 show all --host <IMM_IP> --user <IMM_USER> --password-file <IMM_PASSWORD_FILE>   # read-only, out-of-band
./asu64 show IMM --noimmlancfg                          # read-only on the IMM, but connects over LAN over USB

Note: running ASU without --kcs, --host or --noimmlancfg lets it configure the LAN-over-USB interface on the host (section 3); on this Proxmox host that is a host network change (STATE-CHANGING for the host, CANDIDATE).

STATE-CHANGING (owner approval required):

./asu64 set uEFI.OperatingMode "<value>" --kcs          # STATE-CHANGING (UEFI setting, applies at next boot)
./asu64 setenc <setting> <encrypted_value> --kcs        # STATE-CHANGING
./asu64 loaddefault uEFI --kcs                          # STATE-CHANGING (does not reset boot order, limitation 3)
./asu64 restore <file> --kcs                            # STATE-CHANGING
./asu64 replicate <file> --kcs                          # STATE-CHANGING (skips noreplicate settings)
./asu64 batch <file> --kcs                              # STATE-CHANGING if the batch contains set/restore commands
./asu64 delete <setting>[<instance>] --kcs              # STATE-CHANGING (deletes a setting instance)
./asu64 createuuid <setting> --kcs                      # STATE-CHANGING (sets the system UUID)
./asu64 set IMM.LanOverUsb Disabled --kcs               # STATE-CHANGING (documented to need --kcs, PDF p20)
./asu64 rebootimm --kcs                                 # STATE-CHANGING (IMM restart)
./asu64 generate|import|deletecert ...                  # STATE-CHANGING (IMM certificates)
./asu64 immapp poweronos|poweroffos|rebootos --kcs      # STATE-CHANGING (host power: takes the lab down)
./asu64 immapp clearsel|clearimmlog|clearalllog --kcs   # STATE-CHANGING (log loss)

BIOS-only commands (dump, readraw, writeraw, showlocation) do not apply to this UEFI server (S-026 Chapter 3).

4.6 Caveats (DOCUMENTED unless marked) #

  • "For IMM-based servers, after you use the ASU to change settings, you must reset the IMM before you flash new firmware. If you do not reset the IMM, the changes you made to the settings might be lost" (S-026 PDF p19).
  • Some settings need an IMM restart to take effect or to show in the IMM web interface (S-026 PDF p7).
  • Certificate management needs IMM level "yuoo78m or later" (PDF p7) or "yuoo71a or later" (PDF p19), conflict T-6.

  • --remote=<address> runs compare/update on another server's OS (not the IMM); only Windows-to-Windows or Linux-to-Linux; update over remote is unattended only (S-029 PDF p38, p45).
<uxspi> compare --local=<uxsp_dir>                     # read-only (inventory/compare); uses IPMI/LAN over USB
<uxspi> acquire --local=<dir> ...                      # read-only on the server; downloads from the vendor (network)
<uxspi> update --local=<uxsp_dir> -u                   # STATE-CHANGING (flashes firmware / installs drivers)
<uxspi> update --remote=<os_ip> --remote-user=<user> --remote-password=<pw> ...   # STATE-CHANGING on a remote OS

6.5 Caveats (DOCUMENTED, list only) #

  • The Windows LSI driver is always installed even when the controller is disabled (readme 5.1).
  • Updating the IMM from a USB key unmounts the key; do other updates first (readme).
  • Updates via BoMC, UXSPI, AMM or individual in-band packages take at least 17 minutes; never power off during "Secure Region Update in Progress" (S-022 p9-10, via docs/X3650M3_IMM_ARCHITECTURE.md 9.1).
