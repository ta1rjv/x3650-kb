2. Delivery paths and the host OS constraint #

  • The IBM Linux packages install only on RHEL/SLES; the host runs Proxmox VE (Debian). Verified for the HBA package (install.sh exits 172 on other distributions, STORAGE_RAID 7.1) and DSA (TOOLS 5.7, 9.2); the same PKG SDK wrapper is used by all packages (FIRMWARE_FORMATS 3), so in-band install on the host is CANDIDATE to fail for every package.
  • IMM web interface, Tasks -> Firmware Update (out-of-band, OS independent): documented for IMM 1.55 (README section 2.2) and UEFI 1.22 (README section 2.2). This is the planned path for IMM and UEFI.
  • Bootable media (BoMC, RHEL-based ToolsCenter environment, TOOLS 7) or a temporary RHEL live system: planned path for M1015, HBA and NIC if they are updated at all. NOT VERIFIED on this server.
  • DSA Preboot: iflash64 --package ... --force --bypass_platform over LAN over USB (TOOLS 5.7); needs the IMM USB network (169.254.95.x) from the running OS or boot media. NOT VERIFIED.

3. Preconditions (all before step 1) #

  1. Owner approval of the whole plan and of a maintenance window (UEFI and storage steps reboot the host; all guests stop).
  2. Independent 5 V supply for the OOB Pi, then the deferred serial-console reboot test (STATUS Active Work), so POST/UEFI output of every reboot can be observed and logged.
  3. Backups: vzdump of all guests to a target outside the M1015 virtual disk; ASU export of all UEFI/IMM settings (asu show all, TOOLS) and the IMM configuration backup; copy of /etc/pve.
  4. SEL: it is full and logging stopped since 2025-05-05 (A-008). Save it to captures/ and clear it (owner approval), so flash success/failure events (40000023/40000024, 806f052b failover) are recorded.
  5. Physical access available for jumpers J147 (IMM recovery) and J29 (UEFI boot recovery), and for AC removal.
  6. CMOS battery: Planar VBAT is below its lower critical threshold (1.791 V on 2026-10-20, HARDWARE_COMPONENTS 12); replace the CR2032 before any step that removes AC power, or UEFI settings and clock may be lost.
  7. Record before/after versions for each step (IMM VPD via WS-Man GetVitalProductData, SMBIOS, storcli, ethtool).

4. Order and steps #

Order follows the vendor rule IMM -> UEFI -> DSA (IMM 1.55 README 1.4; FIRMWARE_HISTORY "Update order").

Step Action Host impact Rollback Risk
1 IMM 1.30 -> 1.55 via IMM web Firmware Update; Restart IMM; wait up to 17 min (S-022 p.7) Host keeps running; IMM web/SSH/IPMI and the [remote-access service] IMM hostname drop during restart Backup bank still holds the older image; J147 2-3 boots the secondary page (IMM_ARCHITECTURE 3.2) HIGH: H206034 says 1.30 can fail to start after reset and AC cycling does not recover it (CANDIDATE for 7945); no external SPI recovery path known
1b After 1.55 runs stable: flash the backup IMM bank too (iflash --backup / web option if offered) as step 1 none needed if primary is good Mixed-bank images unpredictable since Q3 2011 (node 860842); do it only after step 1 is verified
2 UEFI 1.13 -> 1.22 primary bank via IMM web; reboot host Full host reboot Backup bank keeps 1.13: J29 2-3 or automatic bank switch; restore by F3 at splash or 15 s AC removal (UEFI 3) MEDIUM: new options take defaults (Limit Boot Attempts default Enable); re-check console redirection and boot order after boot
3 DSA 3.48 -> 9.53 (optional) none (stored on IMM staging volume) re-flash 3.48 not available locally LOW value; image fit on IMM staging volume UNKNOWN (the volume is mounted, not created, by IMM rootfs scripts, so its size comes from the factory flash layout; docs/X3650M3_TOOLS.md 5.7)
4 M1015 20.10.1-0052 -> 20.13.1-0254 from boot media; reboot Host boot disk controller Readme 20.13 1.2: rollback verified only to 20.11.1-0184, 20.11.1-0137, 20.10.1-0107, not to the installed 0052 HIGH data risk: carries the only boot/root virtual disk; full backup mandatory
5 HBA 1.20 via sas2flash from boot media none if non-boot Downgrade/NVDATA downgrade refused by sas2flash (STORAGE_RAID 7.1) LOW (nothing attached), LOW value
6 BCM5709 2.4.1c from RHEL boot media Network outage on both ports Older package 2.1.5b local (older than installed) MEDIUM: Ethernet 1 may be shared with the IMM through NC-SI (CANDIDATE); never use -nomfw / -ncsidisable

5. Recommendation #

  • Do steps 1 and 2 (security and IMM stability); after each, one session to verify and document.
  • Step 1 is the riskiest single action because of H206034; schedule it only after preconditions 2-5 and accept that a failed IMM may need a replacement system board if neither bank starts.
  • Defer steps 3-6: low value (3, 5, 6) or high data risk without proven rollback (4).

6. Open decisions for the owner #

  • Approve or reject the plan; choose the maintenance window.
  • Step 1 risk acceptance (H206034, no external recovery path).
  • Steps 3-6: do, defer or skip.
  • Boot-media choice for steps 4-6 (BoMC versus RHEL live), if any of them is approved.

7. NOT VERIFIED #

  • IMM web firmware update on the installed 1.30 accepting the 1.55 .bin (documented by the 1.55 README for the target, not tested from 1.30).
  • Whether 7945 is affected by H206034.
  • IMM staging volume size for DSA 9.53; 3.48 image size.
  • Any boot-media path on this server.
