2. Architecture and POST flow #

Source S-024 (UEFI intro paper, rev 1.2) unless noted; truth level DOCUMENTED.

  • POST and boot run in four phases (S-024 p.4): (1) IMM initialization and power sequencing, (2) platform initialization, (3) pre-boot DXE, (4) BDS. The firmware follows the SEC, PEI, DXE, BDS model of the UEFI platform initialization specification (diagram S-024 p.4).
  • The early boot code (SEC/PEI) is the contents of Capsule_P.scap in the flash package; DXE drivers and the setup engine live in FvDxe.fv and FvPlatform.fv (EXTRACTED, FORMATS doc section 6). Mapping the phase names to specific FVs follows module names (PeiMain, DxeMain, Bds) and is EXTRACTED.
  • Two boot methods exist, UEFI and legacy (CSM via LegacyBios, EXTRACTED module); the "Legacy Only" flag and boot order storage in NVRAM are described in S-024 pp.5-9.
  • Configuration is stored in two tiers: UEFI NVRAM variables and an IMM-held XML-modelled NVRAM; ASU covers all settings through the XML model (S-024 p.15). Adapter configuration uses HII (S-024 p.16).
  • RAS (S-024 pp.17-18): locked CRTM region (a CRTM update is staged in flash and applied on the next boot; the power-good reset this causes is not a fault), firmware volume integrity service, power-sequence watchdog, POST watchdog (disabled by default; Setup -> System Settings -> Integrated Management Module), dual-bank ABR. Three consecutive boot failures trigger a recovery behavior whose details changed with builds of February 2010 (S-024 p.18).
  • Corruption recovery uses a secure trusted-code region and capsule signature verification (S-024 p.25) and an in-band recovery path (S-024 p.26). The package capsule carries an RSA2048-SHA256 signature trailer (EXTRACTED); tying it to that mechanism is CANDIDATE. POST error 3818006 "Opposite bank CRTM capsule signature invalid" is listed in S-004 (Problem Determination guide, printed p.286, PDF p.304).

3. Firmware banks, recovery and jumpers #

  • Primary and backup UEFI banks (S-004 printed p.372, PDF p.390). To restore the primary: update the primary bank, restart once on the backup, then switch back via AC removal for 15 seconds or by pressing F3 at the splash screen (S-024 p.18; S-004 p.372). Starting the backup server firmware: S-004 PDF p.517.
  • Jumpers (S-004 Table 4, printed p.19, PDF p.37): J29 UEFI boot recovery, pins 1-2 normal (primary), 2-3 backup; J147 IMM recovery, pins 1-2 primary IMM ROM page, 2-3 secondary page. Change only with power off; no jumper behaves as 1-2. This resolves the former UNKNOWN for the IMM recovery jumper in the firmware history document.
  • Flashing the backup bank uses iflash --backup (FORMATS doc section 8). RETAIN tip H196209: updating the UEFI backup firmware with the IMM32F method may fail (S-022 pp.15-16).

4. Setup utility menu tree #

Documented tree (S-002 IUG 11th ed., printed pp.158-162): the F1 prompt opens Setup; with an administrator password set, entering it gives the full menu, otherwise a limited menu. Menu:

  • System Information: System Summary, Product Data.
  • System Settings: Processors, Memory, Devices and I/O Ports, Power, Operating Modes, Legacy Support (Force Legacy Video on Boot, Rehook INT 19h, Legacy Thunk Support), Integrated Management Module (POST Watchdog Timer, value, Reboot System on NMI, Commands on USB Interface Preference, Network Configuration, Reset IMM to Defaults, Reset IMM), Adapters and UEFI Drivers, Network, Storage, Video.
  • Date and Time, Start Options, Boot Manager, System Event Logs (POST Event Viewer, System Event Log, Clear), User Security (power-on and administrator passwords), Save Settings, Restore Settings, Load Default Settings, Exit Setup.

The extracted Front Page form (Bds module, FORM 0x1000, EXTRACTED) matches this: System Information, System Settings, Date and Time, Start Options, Boot Manager, System Event Logs, User Security, Save Settings, Restore Settings, Load Default Settings, Exit Setup; most entries are wrapped in GRAY_OUT_IF on a flag (qid 0x0001, the limited-menu condition; mapping to the password state is CANDIDATE). Compared with 1.14, the only Bds form difference is that in 1.22 the User Security entry is also grayed out under that condition, plus varstore offsets. Other formsets in Bds: System Information (System Summary, Product Data, Reference Code Level, Processor Details Summary), Select one time Boot Device, Boot Manager (Boot Configuration, Driver Options, Add/Delete/Change Boot Option and Order, WOL boot options, Select Next One-Time Boot, Set Time Out Value, Console Options, COM Attribute Setup Page), File Explorer, Date and Time, User Security, System Event Logs. Note: after AC power is applied the power button becomes active about 3 minutes later (S-002 printed p.159).

7. ASU settings (S-026) and the setup XML #

Source of the list: FvOem_Ibm.fv, file 92217677-6658-49ce-8899-a01ec4009790, an XML document (CRLF, references setup.xsl and setup.xsd, product ID "uEFI"), 396724 bytes in 1.22 and 395434 in 1.14 (EXTRACTED). It has three <config> blocks: SYSTEM_CONFIGURATION (mriName "uEFI", 202 settings), ISCSI_ATTEMPT_DATA (mriName "iSCSI", 4) and PXE_CONFIGURATION (mriName "PXE", 3). In addition there are 147 nested <sub-setting> elements (same count in 1.14), each with its own mriName (126 enumerations, 15 text, 6 numeric; 109 protected), for example SpareErrorThreshold under MemoryChannelMode, IdeMode under SataType, WatchdogTimerUefiValue under WatchdogTimerUefi, PcieAspm0..10 in PowerSchemes, 17 per ICH PCI Express root port and 25 iSCSI attempt fields (Appendix A.2). The XML ID attribute is not the ASU name: it differs from mriName for 41 settings (for example ID PowerCapping / mriName EnergyManager, FreqSelect / QPISpeed, TurboHysteresis / TurboBoost, Com1Disable / SerialCOMPort1), and S-026 (ASU v9.30 guide, "uEFI settings in an IMMv1 system", printed pp.23-24) lists the mriName forms (uEFI.EnergyManager, uEFI.SerialCOMPort1, uEFI.LegacyOptionRomPort, ...) and also the sub-settings uEFI.SpareErrorThreshold, uEFI.IdeMode and uEFI.WatchdogTimerUefiValue, so sub-settings are ASU settings too (DOCUMENTED). S-026 (v10.6 guide, printed pp.73-74, "Configuring iSCSI") documents the iSCSI. prefix and instance suffixes such as iSCSI.AttemptName.1; the v9.30 list also shows .1 instance suffixes (uEFI.OnboardDeviceEnable.1).
