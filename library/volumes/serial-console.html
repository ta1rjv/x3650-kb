Goal (owner, 2026-10-20): reach the server console from power-on through UEFI setup, boot menu and an OS installer, remotely via [remote-access service], without the Virtual Media Key. Remote presence (graphical KVM) is a Premium feature and is not licensed on this unit; bypassing the license is out of scope. This plan uses only Standard IMM features: "Serial over LAN" and "Server console redirection" (S-020 text L327-337; remote presence is Premium, L4674-4676). Status: steps 1 and 4 done (UEFI console redirection set with ASU 2026-10-20, readback MEASURED; after the 2026-10-21 08:16 boot the ConIn/ConOut NVRAM variables contain both UARTs, MEASURED, section 1); serial output during POST/setup is NOT VERIFIED (the observed reboot test is deferred); steps 2, 3, 5-9 as in section 8.

Truth levels as in docs/AGENT.md. Sources: sources/text/S-0xx_*.txt line numbers (L), repository captures and docs, official web pages listed in section 9.

1. UEFI settings for console redirection #

IBM's ASU example for IMM servers (S-025, section "SOL (Serial Over LAN) and SP Redirection Configuration", read from sources/pdf/S-025_transitioning_to_uefi_and_imm.doc) and the UEFI 1.22 defaults (docs/X3650M3_UEFI.md Appendix A.1 lines 553-575; installed level is 1.13, same names CANDIDATE):

Setting Default (1.22) Planned value (applied 2026-10-20 unless "unchanged") Status
uEFI.RemoteConsoleRedirection Disable Enable DOCUMENTED (S-025)
uEFI.SerialPortSharing Disable Enable DOCUMENTED (S-025)
uEFI.SerialPortAccessMode Disable Dedicated (never Shared) DOCUMENTED (S-025; IBM RETAIN H205981: a redirection session is lost after an IMM reset when Shared)
uEFI.SPRedirection Disable Enable DOCUMENTED (S-025)
uEFI.SerialCOMPort1 / 2 Enable Enable (unchanged) EXTRACTED
uEFI.LegacyOptionRomPort COM Port 1 COM Port 1 (unchanged) DOCUMENTED: legacy option ROM text goes to one port only
uEFI.Com1/Com2 baud, bits, parity, stop 115200 / 8 / None / 1 unchanged matches measured SOL 115.2 kbps and COM2 115200 (docs/X3650M3_IMM_INTERFACES.md lines 71-72)
uEFI.Com1TextEmul / Com2TextEmul ANSI VT100 DOCUMENTED (S-025)
uEFI.Com1ActiveAfterBoot / Com2ActiveAfterBoot Disable Enable DOCUMENTED (S-025)
uEFI.Com1FlowControl / Com2FlowControl Disable Disable first CONFLICTING: S-025 uses Hardware; IPMI SOL has no RTS/CTS (CANDIDATE); switch only if output is garbled
uEFI.solan Disable (protected) unchanged UNKNOWN effect; try only if SOL stays blank

Applied 2026-10-20 ~23:12 with asu64 batch ... --kcs (RemoteConsoleRedirection, SerialPortSharing, SerialPortAccessMode Dedicated, SPRedirection, Com1/Com2TextEmul VT100, Com1/Com2ActiveAfterBoot Enable; FlowControl left Disable); readback MEASURED (captures/2026-10-20_asu_show_all/README.md).

NVRAM evidence after the next boot (captures/2026-10-21_host_efivars_contents.txt, dump 2026-10-21 ~09:05 after the boot of 08:16:12; MEASURED; details in docs/X3650M3_UEFI.md section 12.3):

  • ConOut (non-volatile): Acpi(PNP0A03,0)/Pci(0x1f,0x0)/Acpi(PNP0501,0)/Uart(115200,8,N,1)/VenMsg(VT100), the same path with Acpi(PNP0501,1), and the video path Acpi(PNP0A03,0)/Pci(0x1c,0x4)/Pci(0x0,0x0)/Pci(0x0,0x0)/AcpiAdr(0x80010100).
  • ConIn (non-volatile): the same two UART paths, the PS/2 keyboard Acpi(PNP0303,0) and any USB HID keyboard UsbClass(0xffff,0xffff,0x03,0x01,0x01). ErrOut is not set.
  • On 2026-10-20 before the change ConOut held only the video path (captures/2026-10-20_asu_show_all/README.md). The new UART instances carry exactly the configured 115200 8N1 and VT100, so the ASU change is effective in NVRAM (MEASURED). PNP0501 UID 0 = COM1 and UID 1 = COM2 is CANDIDATE (section 2).

  • NOT VERIFIED (reboot test deferred until the jump host has its own power supply): that POST, F1 setup, the boot manager and GRUB text actually appear on COM1/COM2, that IPMI SOL and IMM console 1 carry it, and which key sequences work. Not yet measured either: an SPCR table and OS-side console (kernel cmdline has no console=, docs/STATUS.md).

  • The system summary is always shown on text remote consoles including SOL, whatever QuietBoot is (S-024 L950-951).

  • The host boots UEFI (captures/2026-10-20_host_probes_boot_apt.txt), so legacy serial redirection is not used.
  • Function keys over serial: UNKNOWN for IBM firmware. edk2 TerminalDxe maps F1 to ESC 1 (VT100+) or ESC O P (VT100); F12 only in VT100+ (ESC @) (CANDIDATE, to test). Fallback: F1 Setup -> Boot Manager -> one-time boot.

2. Serial port mapping #

  • DOCUMENTED (S-020 L558-580): on System x rack servers COM1 carries IPMI SOL; COM2 is an internal port used for serial redirection over Telnet/SSH (CLI console 1); on blades COM2 is used for SOL.
  • MEASURED (captures/2026-10-19_hw_resources.txt lines 227-228): ttyS0 at 0x3f8 (COM1), ttyS1 at 0x2f8 (COM2).
  • Conclusion (STRONGLY SUPPORTED, not measured): IPMI SOL = COM1 = Linux ttyS0; IMM CLI console 1 = COM2 = Linux ttyS1. CONFLICTING example: the BoMC guide uses console=ttyS1 for SOL (S-030 L1547-1554), which matches blade servers, not this rack server.

3. How to change the UEFI settings #

Method Status Notes
IMM web / CLI not possible IMM v1 has no UEFI setup page; the Serial Port page sets only COM2 baud and CLI mode; no uEFI CLI command (IMM_INTERFACES 3.2, 4.2)
ASU in-band from Proxmox (--kcs) preferred no authentication over KCS; applies at next boot; asu64 save backup and asu64 restore rollback (docs/X3650M3_TOOLS.md lines 193-202). Use --kcs explicitly, otherwise ASU configures LAN-over-USB on the host. Do not set any IMM account or password over KCS (IMM 1.48 fix "password may become empty", IMM_INTERFACES line 284). asu64 needs libcrypt.so.1 (Debian package libcrypt1, presence on the host not checked)
ASU out-of-band (--host [lab-ip]) fallback works with the OS off; needs IMM credentials; port UNKNOWN
F1 setup with local monitor/keyboard fallback needs a site visit

4. Console paths and [remote-access service] #

Path Port Through [remote-access service]
IMM CLI over SSH, then console 1 (COM2 / ttyS1) 22/tcp Browser-rendered SSH will not work: [remote-access service] supports only curve25519 / ECDH key exchange there, while the IMM offers only group1/group14/group-exchange-sha1 and an ssh-rsa 1024 host key (MEASURED, docs/X3650M3_IMM_ARCHITECTURE.md lines 254-258). A client-side [remote-access service] access ssh ProxyCommand relays TCP and can work with legacy OpenSSH options (CANDIDATE).
IPMI SOL, ipmitool -I lanplus -C 3 ... sol activate (COM1 / ttyS0) 623/udp not via a public hostname; WARP private routing with UDP is untested (CANDIDATE). SOL is enabled with forced encryption (MEASURED); use cipher suite 3.

Recommended (CANDIDATE): a small always-on Debian jump host on the LAN, reached with [remote-access service] Access SSH (browser-rendered SSH is fine for a modern host); from it run legacy ssh -tt to the IMM or ipmitool SOL. The SOL client must not run on the x3650 itself: it would die with the host.

5. [remote-access service] connector must not live only on the Proxmox host #

  • MEASURED ([remote-access service]): the only [remote-access service] connector runs on the Proxmox host, so [lab-host] is unreachable whenever Proxmox is off or being reinstalled.
  • DOCUMENTED ([remote-access service] tunnel availability / replicas): a remotely managed tunnel can run up to 25 replicas, but requests go to the closest replica with no steering, so localhost routes break on another replica.
  • Recommended (CANDIDATE): a separate second tunnel on the jump host for out-of-band access (IMM web, IMM SSH, jump host SSH), behind the same Access policy; keep the host tunnel for Proxmox. If replicas are used instead, all routes must use LAN IPs ([lab-ip]:8006, [lab-ip]:80).

6. Installing an OS over the serial console #

  • Proxmox VE ISO: boot entry "Install Proxmox VE (Terminal UI, Serial Console)" uses the first serial port (Proxmox wiki Installation); the installer source builds proxmox-tui-mode console=ttyS0,115200 (pve-installer auto-install-assistant), which matches SOL on COM1. For console 1 edit to console=ttyS1,115200. The installer writes GRUB serial settings into the target when console=ttyS<N>,<speed> is given.
  • Debian 12: console=ttyS0,115200n8 (Debian installation guide 5.3); then Proxmox VE on Debian 12 (Proxmox wiki).
  • Boot media without virtual media:
    1. PXE (UEFI): BCM5709 has an EFI option ROM. PXE boot entries: Boot0003 (not hidden) and the hidden Boot0011/001C/0027/0032 are not in BootOrder; the hidden Boot003D (attributes 0x9) is in BootOrder at position 7, after proxmox, Ubuntu, Hard Disk 0, USB Storage, CD/DVD Rom and Floppy Disk (MEASURED, captures/2026-10-21_host_efivars_contents.txt; all are IBM generic VenMedia entries, docs/X3650M3_UEFI.md section 12.1); one-shot PXE via the IMM web "PXE Network Boot" page (Standard IMM, S-020 L5104-5111) or efibootmgr --bootnext 0003 (CANDIDATE). Debian UEFI netboot (bootnetx64.efi) is documented; PXE-booting the Proxmox ISO is not (a forum report shows the TUI hanging under iPXE). Preferred: Debian netboot over serial, then Proxmox on Debian.
    2. Physical USB stick with the Proxmox ISO, F12 boot menu "USB Key/Disk" (S-002 L6209-6224); needs someone on site.
    3. Debian hd-media installer on a disk that is not being reinstalled.
  • The reinstall target is VD0 (Toshiba) only; VD1 (hitachi-data, backups) must stay untouched.

7. What serial cannot show #

  • Graphical installers, splash screens, OS framebuffer, the IMM "last OS failure screen" (Premium).
  • ServeRAID M1015 WebBIOS (Ctrl+H) is graphical (INFERRED); use storcli from the OS (MEASURED working read-only, docs/X3650M3_TOOLS.md) or F1 -> System Settings -> Adapters and UEFI Drivers (text HII, CANDIDATE over serial).

8. Ordered steps #

# Step Class
1 On the host: ldconfig -p \| grep libcrypt.so.1; read SPCR ACPI table and the ConOut efivar; asu64 save <file> --kcs; asu64 show uEFI --kcs and capture console/COM/PXE values read-only (ASU unpack to scratch)
2 Prepare an always-on LAN jump host: Debian, ipmitool, OpenSSH with legacy options for [lab-ip], its own [remote-access service] tunnel; publish its SSH and the IMM web behind Access change outside the server, owner approval
3 From the jump host: ipmitool -I lanplus -C 3 -H [lab-ip] -U <user> sol info 1; IMM CLI portcfg read-only
4 asu64 set ... --kcs for the values in section 1 (no IMM accounts) setting change, owner approval
5 GRUB on Proxmox: console=tty0 console=ttyS0,115200n8, GRUB_TERMINAL="console serial", GRUB_SERIAL_COMMAND="serial --unit=0 --speed=115200", update-grub setting change, owner approval
6 Reboot with SOL open from the jump host and console 1 in parallel; verify POST, F1, Boot Manager, GRUB; record working key sequences; if blank try uEFI.solan Enable reboot, owner approval
7 Before any reinstall: storcli64 /c0 show all, save VD config; plan RAID changes with storcli read-only
8 PXE/TFTP on the jump host with Debian 12 netboot and console=ttyS0,115200n8 change outside the server, owner approval
9 One-shot PXE, install Debian over SOL, then Proxmox on Debian (or USB stick + serial TUI); then proxmox/REBUILD.md reinstall, owner approval

Step 1 result (2026-10-20, captures/2026-10-20_asu_show_all/README.md): asu64 10.3 runs on the host over KCS with all libraries present; all console-redirection settings are at the defaults in section 1 (MEASURED); ConOut held only the video path, ConOutDev listed a UART path; no SPCR table. Rollback file: [host-path] (host).

Step 4 result: applied 2026-10-20 ~23:12, readback MEASURED; after the 2026-10-21 08:16 boot ConIn/ConOut contain both UARTs (PNP0501 UID 0 and 1 on the LPC bridge Pci(0x1f,0x0), 115200 8N1 VT100) (MEASURED, captures/2026-10-21_host_efivars_contents.txt; section 1). Step 6: the host rebooted 2026-10-21 ~08:12 but the console was not observed (jump host lost power); the observed test is deferred (docs/STATUS.md).

Open items: serial output during POST/setup/boot manager actually seen on SOL and console 1 (step 6), PNP0501 UID-to-COM mapping, SPCR table after the change, uEFI.solan and Console Options effect, F-key sequences, ASU out-of-band port, SOL through WARP UDP, IMM 1.30 handling of IPMI chassis bootdev pxe.
